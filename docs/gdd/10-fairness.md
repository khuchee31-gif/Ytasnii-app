# GDD-10 — Шударга байдал ба заль мэхээс хамгаалах дизайн

> **Шийдвэрийн хураангуй**
> - **Тараалт нь seed-тэй, commit–reveal-тай.** Апп `seed0` (32 байт) үүсгээд түүний hash-ийн **зургаан цифрийн шударга байдлын код**-ыг тараахаас **өмнө** гаргана. Дараа нь утас барихгүй байгаа санамсаргүй суудал дөрвөн цифр нэмнэ. `seed = SHA256("HOTUNTLAA/v1" ‖ dealId ‖ seed0 ‖ userEntropy)`.
> - **Ёслол нь хоёр талтай: тараахын өмнө чангаар уншина, тоглолтын дараа дахин гаргана.** Хөтлөгчийн хоолой зургаан цифрийг хэлнэ, уншигч суудал дэвтрийн буланд бичнэ, тоглолтын төгсгөлд апп мөн тоог дахин тооцоолж гаргана. **Апп өөрөө «тохирлоо» гэж хэзээ ч хэлэхгүй** — харьцуулалтыг хүн хийнэ.
> - **Бүх дүрийг жагсаасан дэлгэц оршихгүй.** Хөтлөгчид ч үгүй, дебаг билдэд ч үгүй, «тохь тухын үүднээс» ч үгүй. `roles` таблиц зөвхөн санах ойд амьдарна, дискэнд хэзээ ч бичигдэхгүй, ялалт код дотор шалгагдана. CI-д grep тест болж хатуурна.
> - **Шөнийн эргэлт бол цагийн хажуугийн сувгийн эсрэг үндсэн механизм.** Суудал бүр яг **6.0 секунд**, дүрээс үл хамааран. Баталгаажуулах товшилт **дэлгэцийг эрт хаахгүй**, ямар ч чичиргээ, ямар ч дуу гаргахгүй. Нэг `mediumImpact` t=0-д, нэг t=5.5 сек-д — бүх суудалд ижил.
> - **Илчлэлт: утсаа өргө + хоёр эрхий + `FLAG_SECURE`.** Хоёр эрхий тавьмагц 100 мс дотор хаагдана, 2.5 секундын дараа автоматаар хаагдана, дэлгэцийн тодрол 20% болно. `FLAG_SECURE`-ийн хамрах хүрээ нь **ОС-ийн зураг авах суваг** — бидний тооцоолж байгаагаар бодит оролдлогын **~70%** [тооцоолол]; үлдсэн ~30% нь хоёр дахь утасны камер, түүнийг ямар ч флаг зогсоохгүй.
> - **Дахин харсныг чангаар зарлана, хэзээ ч бүртгэхгүй.** «№5 дүрээ аль хэдийн харсан.» Тоолуур тоглолтын санах ойд амьдарч, тоглолт дуусахад **устана**. Ангийн дэвтэрт нэг ч суудлын зан үйл бичигдэхгүй.
> - **Бид шагайхыг боломжгүй болгохгүй — ХАРАГДАХУЙЦ болгоно.** Камер байхгүй, микрофон байхгүй, «хэн хэдэн секунд хараа вэ» гэсэн шинжилгээ байхгүй. Арван хоёр хос нүд бол ямар ч сенсорээс хүчтэй.
> - **Татгалзал: мэдээлэх товч байхгүй, нэр заасан байнгын бүртгэл байхгүй, хоёр сурагч гурав дахийг нь «зөрчилтэй» болгох механик байхгүй.** Баталгаажуулах цонхтой дээрэлхэх хэрэгсэл бүтээхгүй.

*Хамаарал: GDD-00 §3 (4-р багана), §5.7, §11. Судалгаа: 10 §0, §2.2–2.4, §3 (P1/P2), 13 §1.1, 11 §4.*

## 1. Юуг зассан гэж дүр эсгэхгүй байх нь

Ширээн дунд нэг утас, хөтлөгч нь ангийн найз. Энэ тохиргоонд заль мэхийн **95% нь техникийн биш, нийгмийн** (10 §0). Тиймээс энэ бүлэг гурван л ажил хийнэ:

| Ажил | Механизм | Ямар заналхийллийг зассан |
|---|---|---|
| Хөзөр тараахыг **нотлогдох** болгох | commit–reveal + seed-тэй Fisher–Yates + тоглолтын дараах шалгалт | T15 — хөтлөгч дүрүүдийг харах, мафи болтлоо дахин тараах |
| Цаг хугацааг **хэлгүй** болгох | Жигд шөнийн эргэлт, 6.0 сек тогтмол, дуугүй баталгаажуулалт | T9 — шөнийн үйлдлийн хугацаанаас дүр тайлах |
| Шагайхыг **харагдахуйц** болгох | Хоёр эрхий, 2.5 сек, `FLAG_SECURE`, дахин харсныг зарлах | T6, T7 — дэлгэцийн зураг, хажуугаас харах |

Бусад бүх заналхийлэл (T1 Discord, T2 биечлэн хамт суух, T4 олон данс, T8 багц задлах, T16 хоригоос зугтах) нь **сүлжээтэй бүтээгдэхүүний асуудал**. v1-д `INTERNET` зөвшөөрөл байхгүй, данс байхгүй, зэрэглэл байхгүй — тиймээс эдгээр нь v1-д **оршихгүй**, бид тэдний эсрэг нэг ч мөр код бичихгүй. Play Integrity, App Check, төхөөрөмжийн кластержилт — бүгд v3.

**Нэг ил үлдээсэн нүх, шударгаар:** хэрэв хөтлөгч **өөрчилсөн APK** суулгавал энэ бүлгийн юу ч түүнийг зогсоохгүй. Өөрчилсөн билд бүх дүрийг шууд харуулж чадна. Бид зөвхөн **Play-ээс татсан жинхэнэ аппыг зүй бусаар хэрэглэхийг** зогсоож байна — дахин дахин тараах, нуугдмал харах, цагаар тайлах. Өөрчилсөн билдийн эсрэг цорын ганц бодит хамгаалалт бол ширээ өөрөө: суулгасан аппыг нь Play-ээс шалгах. Үүнийг тусламжийн дэлгэцэд нэг өгүүлбэрээр бичнэ, дизайнаар шийдэхийг оролдохгүй.

## 2. Seed-тэй тараалт — яг ямар алгоритм

Дараалал нь **хатуу**: суудал түгжих → бүрэлдэхүүн шалгах → амлах → хүний энтропи → тараах. Нэг ч шат сэлгэгдэхгүй.

```
// 1. LOCK — түгжсэний дараа суудал нэмэх/хасах боломжгүй
lockSeats(N, holderSeat)
b = (N div 2) - M - 1
if b < 0  ->  REFUSE, тараахгүй:
   «Энэ бүрэлдэхүүнээр мафи эхний шөнөдөө яллаа. Тоглогч нэм эсвэл мафи хас.»

// 2. COMMIT — юу ч тараагаагүй байхад код төрнө
seed0      = Random.secure().nextBytes(32)
h0         = sha256(seed0)                      // 32 байт
fairCode   = u32be(h0[0..4]) % 1000000          // 6 цифр, «042173» шиг тэгээр нөхнө
dealId     = hex(h0[4..8])                      // 8 hex, бүх дэлгэцийн доод мөрөнд
readerSeat = pickSeat(u16be(h0[8..10]), N, exclude: holderSeat)
render(fairCode, readerSeat)                    // roles ГЭДЭГ ХУВЬСАГЧ ХАРААХАН БАЙХГҮЙ

// 3. REVEAL — хүний энтропи
userEntropy = 4 цифр (readerSeat шивнэ)  |  2.0 сек акселерометрийн дүн (24 сэмпл × 3 тэнхлэг)
seed        = sha256(utf8("HOTUNTLAA/v1") ‖ hex(dealId) ‖ seed0 ‖ userEntropy)

// 4. DEAL
rng   = ChaCha20(key: seed, nonce: 0)            // 256 бит — төлөв хэзээ ч хязгаарлагч болохгүй
deck  = fisherYates(roleMultiset(N, M), rng)
roles = { seat_k : deck[k] }                     // ЗӨВХӨН САНАХ ОЙД

// 5. VERIFY — «Хөзрөө нээе»-ийн ДАРАА
render(dealId, hex(seed0), userEntropy, hex(seed), redealCount, recompute(deck))
```

**`randBelow(n)` — хазайлтгүй:**

```
limit = 2^32 - (2^32 % n)
do { x = u32be(rng.nextBytes(4)) } while (x >= limit)
return x % n
```

Нүцгэн `%` хориотой. Хөвөгч цэгийн үржүүлэлт ч хориотой — тэр нь нарийвчлалаас болж бас хазайдаг (10 §3-ын баталгаажуулалт). Rejection sampling нь хамгийн энгийн зөв арга, бөгөөд **20 суудалд дунджаар 1.00-аас бага дахин татах** тул гүйцэтгэлийн ярилцлага байхгүй.

**Яагаад 256 битийн seed, 20 суудалд 62 бит хүрэлцэх байхад?** Учир нь seed-ийн битийн тоо нь `SHA256`-ийн гарц бөгөөд түүнийг хасах ямар ч хэмнэлт байхгүй (10 §3: 52! нь 226 бит шаардана, ChaCha20 нь хязгаарыг үүрд авчирна). Хямд зөв сонголтыг хийж, дахиж эргэж харахгүй.

**Дахин тараалтын тоолуур — криптографаас илүү хүчтэй.** Хамгийн бодитой заль мэх бол hash эвдэх биш, **таалагдтал дахин тараах** явдал. Тиймээс `redealCount` нь тохиргооны дэлгэцэд байнга харагдана — **«Дахин тараалт: 2»** — түүнийг нуух ямар ч зам байхгүй, тэглэх товч байхгүй, аппыг хаагаад дахин нээвэл тоолуур нь тухайн суултын хугацаанд хадгалагдана. Хоёр дахь тараалтад хөтлөгчийн хоолой нэг мөр нэмнэ: **«Хоёр дахь тараалт.»** Ширээ өөрөө шийднэ.

**Уншигч суудлыг яагаад hash-аас гаргаж байна вэ?** Хэрэв уншигчийг утас барьсан хүн сонговол тэр өөрийн хамсаатнаа сонгоно. `readerSeat` нь `h0`-оос гарна — өөрөөр хэлбэл **кодоо мэдэхээсээ өмнө** тодорхойлогдож, `holderSeat`-ыг хасна. Сонголтыг нь гараар өөрчлөх UI байхгүй.

## 3. Ёслол — 15 секунд, хоёр удаа

Криптограф нь ширээн дээр юу ч нотлохгүй. **Ёслол нотолно.** Тиймээс код нь дэлгэц дээр гарч, дараа нь хоолойгоор хэлэгдэж, дараа нь хүний гараар бичигдэж, дараа нь тоглолтын төгсгөлд дахин гарна.

**Тараахын өмнө (0:20, ~15 секунд):**

| Хугацаа | Дэлгэц | Аудио / үйлдэл |
|---|---|---|
| 0.0 сек | Том цифрүүд: **«04 21 73»**, доор `dealId: 9f3a1c07` | `FAIR_INTRO` — «Шударга байдлын код. Бичиж ав.» |
| 1.6 сек | Цифр бүр дарааллаараа өргөлт авна | Цифрийн клипүүд, **0.4 сек зайтай** («тэг · дөрөв · хоёр · нэг · долоо · гурав») |
| 5.0 сек | **«№9 — кодыг дэвтэр дээр бич.»** | Чимээгүй. Уншигч чангаар дахин уншина. |
| 9.0 сек | **«№9 — утсыг хоёр секунд сэгс.»** эсвэл **«Дөрвөн цифр шив.»** | Акселерометр 2.0 сек хурааж, дараа нь чичиргээ |
| ~13 сек | **«Түгжигдлээ.»** | Тараалт энэ мөчид, өмнө ч биш, хойно ч биш |

**Тоглолтын дараа («Хөзрөө нээе»-ийн дараа, сайн дурын):** нэг товч — **«Шударга байдлын шалгалт»**. Дэлгэц дээр:

```
dealId        9f3a1c07
Код           04 21 73          <-- дэвтэр дээрхтэй харьцуул
seed0         3b9f...c1a2        (64 hex, хуулж болно)
Хүний энтропи 7104
seed          a0d4...9e33
Дахин тараалт 0
№1 Иргэн · №2 Алуурчин · №3 Эмч · ...
```

**Хатуу дүрэм: апп «Тохирлоо ✓» гэж хэзээ ч хэлэхгүй.** Өөрийгөө өөрөө батлах эрх аппад байхгүй — тэр бол яг л хөтлөгчийг «би шударга байсан» гэж хэлүүлэхтэй адил. Дэлгэц зөвхөн тоог гаргана, харьцуулалтыг **дэвтэр барьсан хүн** хийнэ. Дэлгэцийн мөр: **«Дэвтэр дээрх кодтой ижил байна уу?»**

**Яагаад шалгалтын дэлгэц зөвхөн «Хөзрөө нээе»-ийн дараа вэ.** Тэр дэлгэц бүх дүрийг жагсаана. Хаалтын ёслол дүрүүдийг аль хэдийн чангаар хэлсэн байх үед энэ нь шинэ мэдээлэл биш. Тоглолт дуусаагүй байхад ийм дэлгэц оршихгүй — код дотор ч, route дотор ч. `FairnessCheckRoute` нь `GamePhase.revealDone` биш бол `assert`-ээр унана.

> **Би нэг зүйлтэй санал нийлэхгүй байгаагаа тэмдэглэе, дараа нь түүн дагуу дизайн хийнэ.** GDD-00 §7 «Апп шударга байдлын кодыг чангаар хэлнэ» гэж бичсэн. Энэ нь M4a-д **+10 цифрийн клип** нэмнэ, харин M4a бол буулт хийхгүй үе шат. Миний илүү сайн гэж бодож байгаа хувилбар: апп зөвхөн `FAIR_INTRO`-г хэлж, **зургаан цифрийг уншигч суудал өөрөө чангаар уншина** — учир нь ёслолын гол нь тоог **хүн** эзэмших явдал, бөгөөд өртөг нь нэг клип. Гэвч үзэл баримтлал шийдсэн бол шийдсэн: **цифрийн 10 клип M4a-д орно** (~0.3 хөгжүүлэлтийн өдөр, ~120 тэмдэгт аудио), уншигч дараа нь дахин уншина. Хоёулаа болно, ёслол хожно.

## 4. Бүх дүрийг жагсаасан дэлгэц оршихгүй

Энэ бол боломж биш, **бүтцийн шийдвэр**. Хөтлөгчийн самбар байхгүй учраас хөтлөгч юуг ч тохируулж чадахгүй.

| Дүрэм | Хэрэгжүүлэлт | CI-д яаж шалгах |
|---|---|---|
| Дүрийн таблиц дискэнд бичигдэхгүй | `roles` нь `GameSession`-ий `final Map` талбар, `sqflite`-д хүрэхгүй. Ангийн дэвтрийн хуудас тоглолт **дуусахад** нэг л удаа бичигдэнэ | `rg 'roles' lib/data/` → **0 хит** |
| UI давхарга дүрийг зөвхөн эзэн рүү нь өгнө | `roleOf(seat)` дуудлага зөвхөн `reveal_screen.dart` ба `night_action_screen.dart`-д | `rg 'roleOf\(' lib/ui/` нь `reveal_screen.dart`, `night_action_screen.dart`-аас гадуур **0 хит** |
| Дебаг дампын зам байхгүй | `kDebugRoleDump` гэсэн флаг оршихгүй, `print(roles)` оршихгүй | `rg -i 'roleDump' lib/` ба `rg 'print\(.*roles' lib/` → **0 хит** |
| Ялалт код дотор шалгагдана | `checkWin()` нь `M >= T` тооцоолол; өгүүлэмж шийдэгдсэн үйл явдлаас үүснэ, хөтлөгч жагсаалт уншихгүй | `night_engine_test.dart`-ийн golden vector |
| Хасагдахад дүр нээгдэхгүй | Анхдагчаар унтраалттай (GDD-00 §10). Энэ ганц дүрэм хасагдсан хүүхдийн шивнээг **үнэ цэнгүй** болгоно | `settings_test.dart` |

**«Хөтлөгчтэй горим»-ийн онцгой дүрэм.** Тэр горимд нэг хүн шөнийг харна — энэ нь дизайнаар тийм. Тиймээс: (1) дэлгэцийн дээд мөрөнд **байнгын, хаагдахгүй** тэмдэг — **«Энэ төхөөрөмж шөнийг харна»**; (2) хөтлөгчид **дүр тараагдахгүй** — тэр тоглоомын гадна, тоглогч биш; (3) шударга байдлын кодын ёслол **өөрчлөлтгүй** ажиллана, уншигч нь хөтлөгч биш; (4) тэр горимд ч **бүх дүрийг нэг дор жагсаасан дэлгэц гарахгүй** — хөтлөгч шөнийн үйлдлийг **суудал дараалан** хардаг, тараалтын хуудас хардаггүй. Дөрөв дэх нь хамгийн ялгаатай нь: хөтлөгч эргэлтийн турш юу болсныг мэддэг боловч **хэн юу болохыг нэг дэлгэцээс уншиж чадахгүй**, тиймээс мартаж чадна. Хүн мартдаг; жагсаалт мартдаггүй.

## 5. Жигд шөнийн эргэлт — цагийн хажуугийн сувгийн эсрэг

Ширээн дээр утас суудал дараалан аялж байхад **хугацаа бол мэдээлэл**. Хэрэв Алуурчны суудал 6 секунд, Иргэний суудал 2 секунд болвол ширээ гурав дахь шөнөд мафийг цагаар тоолж олно. Тиймээс эргэлт нь дүрээс **бүрэн хамааралгүй** байх ёстой.

| Параметр | Яг утга | Яагаад |
|---|---|---|
| `HANDOFF_MS` | **600 мс** — «Ширээн дээр тавь. Дараах — №7» | Хаагдахгүй, товшилтоор алгасагдахгүй |
| `LIFT_TIMEOUT_MS` | **3000 мс** — үүний дараа «Товшиж нээ» товч гарна | Өргөж чадахгүй хүнд гарц; товч нь бүх суудалд гарна |
| **`NIGHT_SEAT_MS`** | **6000 мс, хатуу** | Баталгаажуулах товшилт **дэлгэцийг эрт хаахгүй**. Бүх суудал яг ижил 6.0 сек |
| Чичиргээ | `mediumImpact` **t = 0 мс**, `mediumImpact` **t = 5500 мс** | Хоёр импульс, бүх суудалд ижил. Хоёр дахь нь «дамжуул» гэсэн дохио |
| Баталгаажуулах товшилтын дохио | **Чичиргээ БАЙХГҮЙ, дуу БАЙХГҮЙ, анимаци БАЙХГҮЙ** | Суудал 1.2 сек-д эсвэл 5.0 сек-д баталгаажуулсан нь хөршид сонсогдвол тэр бол цагийн ул мөр |
| Дуу | `SEAT_TICK`, дамжуулах мөчид, **−18 LUFS тогтмол** | Ижил файл, ижил дуу чимээ, дүрээс хамааралгүй |
| Бай сонгох тор | Бүх суудлын дугаар **өөрийгөө хасаад**, ижил 5×4 тор, ижил хэмжээ | Иргэн ч бүтэн тор харна — торны хэмжээ дүрийг заахгүй |
| Товшилтын тоо | **1 бай + 1 баталгаажуулалт**, ямар ч үл хамаарах зүйлгүй | Эмч, Мөрдөгч, Алуурчин, Иргэн — дөрвүүлээ хоёр товшилт |
| Товшоогүй бол | 6.0 сек дуусахад хоосон үйлдэл. Дэлгэц **өөрчлөгдөхгүй** | Товшоогүй нь харагдах ямар ч ялгаа гаргахгүй |
| Дэлгэцийн цагираг | **Хана цагаар** дүүрнэ (6.0 сек), оролтоос хамаарахгүй | Цагираг нь оролтод хариу үзүүлбэл тэр өөрөө суваг болно |
| Иргэний санамж | **«Хэн сэжигтэй вэ?»** — механикийн хувьд хоосон, гэвч «Хотын шивнээ»-г тэжээнэ | Жигд хуурмаг нь **худал биш** болно: суудал бүрт утас барих үнэнч шалтгаан бий |

**Хамгийн чухал мөр нь тэр «эрт хаахгүй» гэдэг нь.** Шөнийн эргэлт дээр өөр бүх апп үйлдэл ирмэгц дараагийн дэлгэц рүү шилждэг — тэр нь хамгийн хямд, хамгийн тааламжтай, **бүрэн эвдэрсэн** зан үйл. 12 суудал × 6.0 сек = **72 секунд**, ФСМ-ийн шөнөөс богино (GDD-00 §7).

**Мафи хэд байх нь эргэлтийг өөрчлөхгүй.** Гурван мафи нь **тус тусдаа** товшино, апп олонхиор шийднэ, тэнцвэл **Ахлагчийн** товшилт хожно — нэмэлт дэлгэц, нэмэлт секунд, «хамтдаа шийд» гэсэн дугуй **байхгүй**. Мафийн суудал нь Иргэний суудлаас цагаар ч, товшилтын тооноор ч, чичиргээгээр ч ялгарахгүй.

**Юуг зориуд хийхгүй вэ:** jitter. 10 §2.2 нь `T0 + U(0, 1500 мс)` санамжийн jitter-ийг зөвлөдөг — тэр нь **олон төхөөрөмж зэрэг** ажиллаж байхад л утга бүхий. Нэг утас дараалан аялахад jitter нь эргэлтийг зөвхөн урт болгоод, ширээнд «яагаад миний хэсэг урт байсан бэ» гэсэн хуурамч дохио үүсгэнэ. **v1-д jitter байхгүй. Тогтмол 6.0 сек нь илүү хүчтэй хамгаалалт** — учир нь хэлбэлзэл нь өөрөө хэмжигдэх зүйл, тогтмол нь биш.

## 6. Илчлэлт — өргө, хоёр эрхий, `FLAG_SECURE`

| Шат | Яг тодорхойлолт |
|---|---|
| Утас хавтгай эсэхийг шалгах | `abs(a_z) ∈ [0.85, 1.15] g` ба `abs(a_x), abs(a_y) < 0.25 g`, **250 мс** тогтвортой → сануулга: **«Утсаа өргө — бусад хараад байна.»** Дараа нь **хэвээр нээгдэнэ** (GDD-00 §5.7: татгалзал биш, сануулга) |
| Хоёр эрхийн бариул | Доод хоёр буланд **96 × 96 dp** хоёр талбай. **Хоёулаа зэрэг** дарагдсан байх ёстой |
| Аль нэгийг тавихад | **100 мс дотор** хөзөр алга болно, `AnimatedOpacity` 100 мс |
| Хугацааны дээд хязгаар | **2.5 сек**, дараа нь автоматаар хаагдана. Дахин дарж нээж болно (§7-ын үнээр) |
| Тодрол | Илчлэх route-д дэлгэцийн тодрол **20%** болно, гарахад өмнөх утга сэргэнэ |
| Өнгө | `#0E1A2B` суурин дээр бага контрасттай хөзөр. Утга нь **өнгө БА хэлбэр БА кирилл шошго** |
| `FLAG_SECURE` | Зөвхөн илчлэх route-д `addFlags`, гарахад `clearFlags` |

**Яагаад хоёр эрхий, нэг эрхий биш.** Хоёр гар банзал болмогц утсыг хажуу тийш **хазайлгах** ч, хөршид **дамжуулах** ч боломжгүй болно. Дээрээс нь хоёр эрхийн байрлал нь ширээн дээгүүр **харагдана** — хэн хөзрөө харж байгааг арван нэгэн хүн нэг харцаар мэднэ. Энэ бол хамгаалалт биш, **биеийн хэл**.

**`FLAG_SECURE`-ийн ~70%-ийн буулт, шударгаар.** Флаг нь ОС-ийн дэлгэцийн зураг, дэлгэцийн бичлэг, аюулгүй бус гадаад дэлгэцийг блоклоно, бас recents-ийн урьдчилан харахыг ч бүдгэрүүлнэ — үнэгүй нэмэлт. Ангийн ширээнд бодитоор тохиолдох зургийн оролдлогын **~70% нь ОС-ийн зураг** (Messenger-т шидэх гэсэн рефлекс), **~30% нь хоёр дахь утасны камер** [тооцоолол — хэмжсэн тоо биш, M2.5-д ажиглалтаар шалгагдана]. Хоёр дахь утасны камерыг **ямар ч флаг, ямар ч сенсор зогсоохгүй** бөгөөд бид оролдохгүй: 2.5 секунд, 20% тодрол, бага контраст нь камерын кадрыг уншихад хэцүү болгодог — тэр бол **үнэгүй** давуу тал, дизайны амлалт биш.

**Платформын шууд дүгнэлт:** v1 бол **зөвхөн Android**, тиймээс `FLAG_SECURE` нь v1-ийн хэрэглэгчдийн **100%**-ыг хамарна. iOS ирэхэд (v3) блоклох боломж **бүрмөсөн байхгүй** — зөвхөн `userDidTakeScreenshotNotification`-оор илрүүлээд **чангаар зарлана**: «№4 дэлгэцийн зураг авлаа.» 11 §-ын тооцооллоор өсвөр насны үзэгчийн 60–70% нь Android, өөрөөр хэлбэл v3-д хэрэглэгчийн **~30–40%** блоклолтгүй, зөвхөн зарлалтай үлдэнэ. Энэ бол v3-ийн шийдвэр, v1-ийн код биш.

## 7. Дахин харсныг чангаар зарлах — гэхдээ хэзээ ч бүртгэхгүй

Хөзрөө хоёр дахь удаа нээх нь заль мэх биш. Мартах бол хэвийн, ялангуяа эхний тоглолтод. Гэвч дахин нээх нь **хажуугийн хүнд өөр боломж** бас өгдөг. Тиймээс механизм нь шийтгэл биш, **мэдээлэл**:

| Үйл явдал | Юу болох |
|---|---|
| Суудал 1-р удаа нээх | Юу ч зарлагдахгүй |
| Суудал 2 ба дараагийн удаа нээх | Илчлэхийн **өмнө** бүх ширээнд 1.5 сек баннер: **«№5 дүрээ аль хэдийн харсан.»** Дараа нь хэвийн нээгдэнэ |
| Тоглолт дуусах | `viewCount` **устана**. Ангийн дэвтэрт ямар ч мөр бичигдэхгүй |

**Яагаад бүртгэхгүй вэ.** GDD-00 §11.3: *сурагч сурагчийг албан ёсоор шийтгэх ямар ч механик гаргахгүй.* «Дахин харсан: №5 (2)» гэсэн мөр дэвтэрт бичигдмэгц тэр нь **нэр заасан байнгын бүртгэл** болно, бөгөөд хоёр долоо хоногийн дараа ангийн хэрүүлд иш татагдана. Тиймээс тоолуур нь тухайн мөчид чангаар ажиллаж, тоглолт дуустал амьдарч, дараа нь **үхнэ**. Ширээ түүнийг санавал санана — тэр бол ширээний ажил, аппын биш.

Дэвтэрт бичигдэх шударга байдлын **цорын ганц** зүйл нь `dealId` ба зургаан цифрийн код. Тэр хоёр нь тараалтын талаарх маргааныг долоо хоногийн дараа ч шалгах боломж өгнө, бөгөөд **ямар ч суудлын зан үйлийг** дүрсэлдэггүй.

## 8. Апп юуг зориуд ЗОГСООХГҮЙ вэ

Энэ бол хамрах хүрээний өмнөх дизайны шийдвэр: **бид шагайхыг боломжгүй болгохгүй, ХАРАГДАХУЙЦ болгоно.** Шалгах асуулт нь үргэлж нэг: *«Ширээ энэ явдлыг харж байна уу?»* Хэрэв тийм бол апп нэмэх зүйл байхгүй.

| Юу | Яагаад зогсоохгүй вэ |
|---|---|
| Хөрш дэлгэц рүү харах | Камер, нүдний хяналт, «хэн харж байна» илрүүлэлт — бүгд **хориотой**. Хоёр эрхий, 20% тодрол, 2.5 сек нь шагайхыг **хэцүү ба харагдахуйц** болгоно, тэгээд л боллоо |
| Хоёр дахь утасны камер | Техникийн хувьд боломжгүй. Оролдвол л хуурамч аюулгүй байдал зарна |
| Утсыг дараалалгүй дамжуулах | Апп зөвхөн **«Дараах — №7»** гэж чангаар хэлнэ. Хэн нэг нь дараалал алгасвал арван нэгэн хүн шууд мэдэх — дүрмээр хаах шаардлагагүй |
| Хасагдсан хүний шивнээ | **Дүр нээгддэггүй** тул шивнэх юм байхгүй. Мэдээллийн зохиомж нь илрүүлэлтийг үүрд орлоно |
| Хөтлөгч, тоглогчийн худал | **Худал хэлэх бол хүний ажил** (GDD-00 §3, 3-р багана). Апп зөвхөн амьд тоглогчийн үйлдлээс үүссэн худал баримт дамжуулна |
| Аппыг гараар сонсоох, файл ухах | v1-д дүр дискэнд **байхгүй** тул ухах юм байхгүй. Root илрүүлэлт байхгүй |
| Цаг хугацаа сунжрах, «хэтэрхий удаан харав» | Хэмжихгүй, бүртгэхгүй, зарлахгүй. 2.5 секунд бол бүгдэд ижил |
| Тоглолтоос гарах, зориуд алдах | v1-д зэрэглэл байхгүй тул алдахад ямар ч ач холбогдол байхгүй |

**Хамгийн хүчтэй хамгаалалт нь код биш байсан.** «Хасагдахад дүр нээгдэхгүй» + «бүх дүрийн дэлгэц оршихгүй» + «жигд 6.0 секунд» гурав нь хамтдаа **нэг хөгжүүлэлтийн өдрөөс бага** зардалтай боловч T5, T15, T9-ийг гурвуулангийг үнэ цэнгүй болгоно. Сенсор нэг ч байхгүй.

## 9. Татгалзал — дахин, ил тод

1. **Мэдээлэх товч байхгүй.** «Хууран мэхэлсэн гэж мэдэгдэх» товч ч, маягт ч, «шалгах» дараалал ч байхгүй. v1-д мэдээлэл хүлээж авах хүн ч, сервер ч байхгүй — тиймээс товч нь **гүйцэтгэгдэхгүй амлалт** болно.
2. **Нэр заасан байнгын бүртгэл байхгүй.** Дахин харсан тоо, шагайсан тоо, «итгэлийн оноо», хөтлөгчийн зэрэглэл — нэг ч зүйл суултаас хойш амьдрахгүй. Хадгалагддаг зүйл нь `dealId` ба код л.
3. **Хоёр сурагч гурав дахийг нь «зөрчилтэй» болгох механик байхгүй.** «Зөрчил» санаа нь **засваргүйгээр татгалзсан** (GDD-00 §11.3): *«Энэ бол шүүгч биш — энэ бол баталгаажуулах цонхтой дээрэлхэх хэрэгсэл.»* Хоёр хүний баталгаажуулалт нь шударга байдлыг биш, **бүлэглэлийг** л баталгаажуулна.
4. **Мэдээлэл ба тоглоомын хүч зарахгүй.** Шударга байдал нь мөнгөтэй хэзээ ч холбогдохгүй: «шалгалтын дэлгэц» үнэгүй, «дэлгэцийн зураг хамгаалалт» үнэгүй. Мөнгөөр авах боломжтой зүйл нь зөвхөн хөзрийн ар тал ба хоолой.
5. **Апп өөрийгөө өөрөө батлахгүй.** «Тохирлоо ✓» гэсэн мөр хэзээ ч гарахгүй. Тоо гарна, хүн шийднэ.

## 10. Тест — шударга байдал бол хийсвэр үг биш, CI-д унадаг зүйл

Дөрвөн багана код review-ийн дүрэм болсонтой ижилхэн, энэ бүлэг **гүйдэг тест** болно. Хэрэв доорх тав нь ногоон биш бол билд гарахгүй.

| Тест | Юу шалгана | Файл |
|---|---|---|
| `deal_golden_test` | Гурван бэхжүүлсэн вектор: `(seed0, userEntropy, N, M)` → **яг тэр** суудал–дүрийн жагсаалт. Тараалт детерминист гэдгийг мөнхөд түгжинэ | `test/fairness/deal_golden_test.dart` |
| `deal_uniformity_test` | 200,000 тараалт, N=12, M=3: суудал тутмын мафийн давтамж **0.25 ± 0.004** дотор. `randBelow`-ийн хазайлтыг барина | `test/fairness/uniformity_test.dart` |
| `night_timing_test` | Дөрвөн дүрийн суудлын эргэлт **бүгд 6000 ± 16 мс**. Баталгаажуулалтыг 200 мс-д оруулбал ч 6000 мс хэвээр | `test/fairness/timing_test.dart` |
| `no_role_leak_test` | §4-ийн дөрвөн `rg` дүрэм скрипт болж гүйнэ; хит гарвал **унана** | `tool/check_no_role_leak.sh` |
| `no_internet_test` | `AndroidManifest.xml`-д `INTERNET` мөр байвал унана (GDD-00 §3) | `tool/check_manifest.sh` |

**`deal_uniformity_test` яагаад хэрэгтэй вэ.** Нүцгэн `%`-ийн хазайлт нь **нүдэнд харагдахгүй** — 12 суудалд хазайлт нь ~0.0000003% тул хэн ч анзаарахгүй. Гэвч тест байхгүй бол хэн нэг нь (жишээ нь чи, 1-р сарын 2-нд, 23:40-д) rejection sampling-ийг «хэт удаан» гэж хасах бөгөөд түүнийг хэн ч барихгүй. **Тест нь хазайлтыг барихын тулд биш, шийдвэрийг барихын тулд бий.**

**Нэг гараар хийх ажиллагааны шалгалт, M2.5-д:** секундомер гартаа авч, арван хоёр суудлын эргэлтийг **гурван шөнө** хэмж. Хэрэв нэг ч суудал 6.0 секундээс 0.3 секунд зөрвөл `NIGHT_SEAT_MS`-ийн хэрэгжүүлэлт эвдэрсэн (магадгүй `just_audio`-ийн 1–3 минутын тасалдал, 18 §3 эрсдэл 6). Тэр зөрүү бол цагийн суваг өөрөө.

## Нээлттэй асуулт

| Асуулт | Яаж хэмжих | Хариу нь юуг өөрчлөх |
|---|---|---|
| **1. Уншигч кодыг үнэхээр бичиж авав уу?** | Таван тоглолтод тоол: дэвтэр/самбар дээр бичигдсэн эсэх | 0/5 бол ёслол нь театр. **Кодыг хэвээр гаргана** (15 секунд л) боловч «бичиж ав» гэсэн мөрийг **«чангаар уншаад дамжуул»** болгож солино |
| **2. Зургаан цифр монголоор 10 секундэд уншигдав уу?** | Секундомер, уншигчийн уншсан хугацаа | >15 сек бол **дөрвөн цифр** болгож хасна, эсвэл v2-ын «үгтэй код» мөрийг татна |
| **3. Хэн нэг нь «яагаад?» гэж асуув уу?** | Ажиглалт, таван тоглолт | Хэн ч асуухгүй бол тайлбарыг тусламжийн дэлгэцээс **хасна** — ойлгогдоогүй ёслол ч ажилладаг, харин уншигдаагүй тайлбар ажилладаггүй |
| **4. Ширээ мафийг **цагаар** тайлж чадав уу?** | 3-р тоглолтын дараа хүйтнээр асуу: «Хэн алуурчин болохыг хугацаагаар таасан уу?» | Хэн нэг нь тийм гэвэл **суваг бий** — эхлээд баталгаажуулах товшилтын анимаци, дараа нь `SEAT_TICK`-ийн дуу чимээ шалгагдана |
| **5. Хоёр эрхий хэдэн удаа гулсав?** | 12 тараалтад бүтэлгүй нээлтийн тоо | >2 бол бариулыг **120 × 120 dp** болгоно; >4 бол **нэг эрхий** болгож буулт хийнэ (харагдах байдал нь хямдардаг) |
| **6. «№5 аль хэдийн харсан» инээд үү, ичгүүр үү?** | Таван тоглолтын хариу үйлдлийг ажигла | Тавын хоёрт ичгүүр бол баннерыг **дуугүй жижиг тэмдэг** болгож бууруулна — зарлах нь зорилго, шившиглэх нь биш |
| **7. Хэн нэг нь дахин тараахыг оролдов уу?** | `redealCount` > 0 болсон тоглолтын тоо | Тэг бол тоолуур нь үнэгүй даатгал (0.2 өдөр, үлдэнэ). Байвал §2-ын «Хоёр дахь тараалт» аудио мөр нь **зөв** болсон гэсэн үг |
| **8. Бодит шагайлт хэдэн удаа болов?** | Ажиглалт, таван тоглолт × 12 тараалт | Тэг бол 2.5 секундыг **2.0** болгож, тараалтыг 90 → 75 секунд болгож хурдасгана. 5-аас их бол шагайлт нь дизайны асуудал биш, **ширээний зохион байгуулалтын** асуудал — тусламжийн дэлгэцэд «дараалал нь цагийн зүүний дагуу» гэж нэмнэ |

**Юу нь энэ бүлгийг бүхэлд нь эргүүлэх вэ.** Зөвхөн нэг зүйл: хэрэв M2.5-д ширээ шударга байдлын ёслолыг **хоёр дахь тоглолтод алгасах** гэж хүсвэл (өөрөөр хэлбэл 15 секунд нь 22 минутын тоглолтын хэмнэлийг хугална), код нь **тохиргоонд шилжинэ** — анхдагчаар асаалттай, «Ёслолыг алгасах» гэсэн нэг шилжүүлэгтэй, бөгөөд алгассан тоглолтын дэвтрийн хуудсанд **«Код уншигдаагүй»** гэж бичигдэнэ. Тэгсэн ч `seed0`, `dealId`, шалгалтын дэлгэц бүгд **өөрчлөлтгүй** ажиллана: нотолгоо нь ёслолоос хамаарахгүй, зөвхөн ширээний **итгэл** ёслолоос хамаарна.
