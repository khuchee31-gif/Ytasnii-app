# GDD-05 — Шөнийн хөдөлгүүр — техникийн тодорхойлолт

> **Шийдвэрийн хураангуй**
> - **v1-ийн бүх шөнө нь `resolveNight(NightState, List<Intent>) -> NightReport` гэсэн ганц цэвэр функцээр шийдэгдэнэ.** IO байхгүй, `DateTime.now()` байхгүй, `Random()` байхгүй, `double` байхгүй. Хөдөлгүүр нь Flutter-ээс хамаарахгүй, `dart:io`-гүй тусдаа багц.
> - **Эрэмбийн шат 17 хувингаас 8 болж хумигдав.** v1-д зөвхөн `10 setup · 90 protect · 100 attack · 120 deathApply · 130 info · 135 whisper · 160 messages · 170 winCheck` ажиллана. 20–80 ба 140–150 нь **хоосон байх нь тестээр шалгагдана** — тэнд v2-ын дүрүүд суух зай.
> - **Мөрдөгчийн хариу товших мөчид өгөгдөнө, үүрээр биш.** v1-д хуурах дүр байхгүй тул `INFO` бусад бүх хувинтай коммутатив болж, шалгалтын үр дүн шөнийн бусад үйлдлээс үл хамаарна. Энэ ганц дүгнэлт үүрийн хувийн дэлгэцийн бүхэл давхаргыг устгав.
> - **v1-д хувийн мессеж ЗӨВХӨН нэг л байна: Мөрдөгчийн «Мөр олдлоо».** Эмчид «аварлаа» гэж хэлэхгүй, хохирогчид «чам руу довтолсон» гэж хэлэхгүй — нийтийн `DAWN_NO_KILL` мөр хоёуланг нь хийж байна, бөгөөд тэр мөрийн **хоёрдмол байдал нь зориудын** (§9.2).
> - **«Тооны самбар» нь дүрийг хэзээ ч уншихгүй.** `pips = b₀ − (dayIndex − 1)`, бөгөөд `b₀ = ⌊N/2⌋ − M − 1`. Хасагдсан хүний талыг уншиж буулгавал апп нь хасагдсан хүний дүрийг чимээгүйхэн зарлана — тэр нь `00-vision` §11-ийн 1-р татгалзлыг зөрчинө.
> - **Шударга байдлын код: `seed0` (32 байт) → SHA-256 → зургаан аравтын тоо, `412-995` хэлбэрээр**, хуваарилахаас **өмнө** утас барихгүй байгаа тоглогч цаасан дээр бичнэ. **Seed-ийн гарал нь GDD-10 §2-ынх**, энд давтагдахгүй: `seed = sha256(utf8("HOTUNTLAA/v1") ‖ hex(dealId) ‖ seed0 ‖ userEntropy)`, `dealId = hex(h0[4..8])`. ChaCha20 урсгал, rejection sampling-тай Fisher–Yates.
> - **Дахин шийдвэрлэлт идемпотент, санамсаргүй бус.** `inputHash` таарвал кэшлэгдсэн байтыг буцаана; таарахгүй бол **дахин тооцоолохгүй**, бүртгэлээс бүтнээр дахин тоглуулна. **Бүртгэл ба кэш нь GDD-12-ын `game_event` дотор амьдарна** — энэ бүлэг өөрийн `event` хүснэгт үүсгэхээ больсон (§6).
> - **Чимээгүйн хүснэгт нь UI-ийн код биш, хөдөлгүүрийн гаралт.** `NightReport.cues` дотор `pause2500` нь `killA` ба `killB`-ийн хооронд байх нь **инвариант N14** (GDD-13 §4).

*Уг баримт: `docs/03-night-engine.md` (17 хувин, 18 парадокс) — тэндээс v1-ийн бүрэлдэхүүн хүртэл нарийсгав. Нэр томьёо: `docs/13-language-culture.md` §1. Шударга байдал: `docs/10-anticheat.md` §3 протокол P2.*

## 1. Хамрах хүрээ — юуг шийдвэрлэх хөдөлгүүр вэ

v1-д таван дүр байна, дөрөв нь шөнө үйлдэл хийнэ. **Иргэн ч үйлдэл хийнэ** — түүний товшилт нь механикийн хувьд хоосон биш, «Хотын шивнээ»-г тэжээнэ.

| Дүр (монгол) | `Role` | Фракц | `Ability` | Хувин | Суудал |
|---|---|---|---|---:|---|
| Алуурчин | `killer` | `mafi` | `mafiaKill` | 100 | бүгд |
| Ахлагч | `boss` | `mafi` | `mafiaKill` | 100 | **зөвхөн `M ≥ 3` (N ≥ 12)** |
| Эмч | `doctor` | `hotynhon` | `heal` | 90 | бүгд |
| Мөрдөгч | `detective` | `hotynhon` | `investigate` | 130 | бүгд |
| Иргэн | `citizen` | `hotynhon` | `suspect` | 135 | бүгд |

**Гурван хатуу дүрэм, эндээс гарч ирдэг:**

1. **Амьд суудал бүр шөнө бүр яг нэг `Intent` илгээнэ.** Харагдах **`Алгасах` товч байхгүй** (GDD-02-оос хасагдав — тэр нь хэн алгассаныг ширээнд харуулдаг суваг). Гэвч **товшихгүй өнгөрөх нь боломжтой**: цонх дуусахад `ability = noAction` бүхий `Intent` бүртгэгдэнэ, дэлгэц өөрчлөгдөхгүй, чимээ ижил, гаднаас нь товшсонтой **ялгагдахгүй** (GDD-06 S09-ийн `timeout`). *(Энэ бүлэг өмнө нь «таймер байхгүй, автомат алгасалт байхгүй» гэж бичдэг байсан. Тэр нь бодит ширээн дээр **хэрэгжүүлэх боломжгүй** — хэн нэг нь утсыг зүгээр дамжуулна — бөгөөд GDD-06, GDD-07-ын `CIRCUIT_TIMEOUT`/`ACT_NONE`, GDD-11 §Q2-ын хэмжилт, GDD-13 §4.2-ын fuzz дөрвүүлээ түүнийг зөрчиж байв.)*
2. **Бүх дүр ижилхэн 6 секунд, ижил чичиргээ, ижил чимээ.** Хөдөлгүүрийн хувьд энэ нь: `Intent`-ийн хэлбэр дүрээс хамаарахгүй — `(actor, ability, target)`. Дэлгэцийн асуулт л өөр.
3. **Хөдөлгүүр хэзээ ч худлаа хэлэхгүй.** Хорлогч (framer), Согтуу, Даяанч байхгүй. Тиймээс `frames` map нь v1-д **байхгүй**, `investigate` нь дүрийн фракцийг шууд уншина.

## 2. Төрлүүд (Dart)

Хөдөлгүүр бол `packages/engine` — цэвэр Dart, `pubspec.yaml` дотор `flutter` ч, `dart:io` ч байхгүй. Ингэснээр CLI дээр (M1) ба апп дотор (M2) **ижил байт** ажиллана.

```dart
typedef Seat = int;            // 1..20. Дэлгэцэн дээрх дугаартай ЯГ ижил. Индекс биш.

enum Role     { killer, boss, doctor, detective, citizen }
enum Faction  { mafi, hotynhon }
enum Ability  { mafiaKill, heal, investigate, suspect, noAction }

enum AttackLevel  { none, basic, powerful }   // v1: none, basic
enum DefenseLevel { none, basic }             // v1: none, basic

enum RejectCode {
  actorDead, targetDead, targetSelf, targetSameFaction,
  notYourAbility, healRepeat, nightSealed, seatNotInGame,
}
// targetSelf ба targetSameFaction нь ТОХИРГООНООС хамаарна (§2-ын Setup):
// doctorSelfHeal = unlimited|once|never,  mafiaFriendlyFire = true|false.

@immutable
class Intent {
  final String  intentId;     // uuid v4, клиент үүсгэнэ — идемпотентын түлхүүр
  final int     night;        // 1-ээс
  final Seat    actor;
  final Ability ability;
  final Seat?   target;       // ability == noAction үед л null
  final int     clientSeq;    // суудал тутам монотон; (actor, ability) тутам сүүлийнх нь хожино
  final int     submittedAtMs;// ЗӨВХӨН аудит. Эрэмбэлэхэд хэзээ ч биш.
}

@immutable
class Setup {
  final int n;                          // 6..20, тэгш тоо зөвлөмжтэй
  final Map<Seat, Role> roleBySeat;     // НУУЦ. UI хэзээ ч бүтнээр рендерлэхгүй.
  final FactionRule factionRule;        // §4
  final bool whisperOn;                 // анхдагч true (ангийн багц)
  final bool narration;                 // false = «Хөтлөгчтэй горим»
  final int  whisperMinAgree;           // анхдагч 3
  // --- GDD-03-ын гэрийн дүрмийн toggle-ууд. Эдгээргүйгээр тэр toggle-ууд
  //     буудаг газаргүй үхмэл текст болно (GDD-15 §2).
  final SelfHeal doctorSelfHeal;        // unlimited | once | never (анхдагч once)
  final bool     mafiaFriendlyFire;     // анхдагч true
  final int      nightSeatMs;           // тоглолт эхлэхэд царцсан, суудал бүрт ИЖИЛ
}

@immutable
class NightState {
  final Setup      setup;
  final int        night;
  final Set<Seat>  alive;
  final Map<Seat, Seat> lastHealTarget;  // Эмч тутам, өнгөрсөн шөнийн бай
  final Uint8List  seed;                 // 32 байт
  final List<Seat> orderPerm;            // seed-ээс гарсан, GameCreated-д бичигдсэн
  int rank(Seat s) => orderPerm.indexOf(s);   // n ≤ 20, O(n) хангалттай
}

@immutable
class Death   { final Seat victim; final Seat killer; final DeathTag tag; }
@immutable
class Visit   { final Seat from, to; final Ability ability; final bool harmful; }
@immutable
class Msg     { final MsgCode code; final Map<String,int> params; }

@immutable
class NightReport {
  final int              night;
  final List<Death>      deaths;        // v1: 0 эсвэл 1
  final List<Seat>       whisper;       // 0..2, суудлын дугаараар ӨСӨХӨӨР
  final Map<Seat,List<Msg>> privateMsgs;// v1: ≤ 1 бичлэг (Мөрдөгч)
  final List<Cue>        cues;          // хөтлөгчийн дохио + чимээгүйн блокууд
  final List<Visit>      visits;        // эргэн харах дэлгэц + дибаг
  final WinState         win;
  final String           inputHash;     // sha256(canon(sealed input))
  final String           resultHash;    // sha256(canon(this))
}
```

**Санаа илгээнэ, үр нөлөө биш.** Утас `{ability: mafiaKill, target: 7}` илгээнэ, хэзээ ч «7 үхлээ» гэж илгээхгүй. Хэн үхсэнийг **зөвхөн** `resolveNight` шийднэ. Офлайн горимд «сервер» гэдэг чинь яг тэр утсан дээр ажиллаж байгаа тэр л функц — яг үүний улмаас хөдөлгүүр IO-гүй байх ёстой.

**Шалгалт нь илгээх мөчид болно, шийдвэрлэх үед хэзээ ч биш.** `validate(Intent, NightState) -> RejectCode?` бол цэвэр функц, дэлгэц нь түүний кодыг монгол текст болгоно. Шийдвэрлэх үед дахин шалгавал инвариант N6 эвдэрч, дахин тоглуулалт зөрнө.

| `RejectCode` | Нөхцөл | Дэлгэцийн текст |
|---|---|---|
| `targetSelf` | Мөрдөгч, Иргэн өөрийгөө онилов; **Эмч нь `doctorSelfHeal`-ээс хамаарна** (`never`, эсвэл `once` бөгөөд аль хэдийн хэрэглэсэн) | «Өөрийгөө сонгож болохгүй.» |
| `targetSameFaction` | Мафи мафиг онилов **бөгөөд `mafiaFriendlyFire == false`** | «Өөрийнхнөө сонгож болохгүй.» |
| `healRepeat` | Эмч өнгөрсөн шөнийн байгаа нь дахин онилов | «Өчигдөр аварсан хүнээ дахин аварч болохгүй.» |
| `targetDead` | Бай `alive` дотор байхгүй | «Тэр тоглогч хасагдсан.» |
| `nightSealed` | Шөнө аль хэдийн лацдагдсан | «Энэ шөнө хаагдсан.» |

## 3. Түвшин ба эрэмбийн шат

### 3.1 Довтолгоо / хамгаалалтын түвшин

```dart
bool lethal(AttackLevel a, DefenseLevel d) => a.index > d.index;
```

v1-д яг **хоёр** утга ажиллана: мафийн хутга = `basic` (1), Эмчийн олгосон хамгаалалт = `basic` (1). `1 > 1` нь хуурамч тул **эдгээлт нь мафийн алалтыг чанд цуцална**. `powerful` нь v2-д (Манаач, Хамгаалагч) зориулж enum дотор сууж байна, гэхдээ **v1-д хөдөлгүүр `powerful` хэзээ ч гаргахгүй** — инвариант N13 үүнийг шалгана.

Яагаад тэнцүү түвшин гэж? Хэрэв Эмчийг `powerful` олгодог болговол ирээдүйн «хүчтэй алуурчин» дүр Эмчийг дийлэхгүй болно. Тэнцүү түвшин нь дизайны зайг үлдээнэ.

### 3.2 Эрэмбийн шат — зөвхөн манай дүрүүд

| Хувин | Нэр | v1-д хэн байна | Тайлбар |
|---:|---|---|---|
| 10 | `setup` | — | шөнийн тоолуур, `lastHealTarget` шинэчлэл |
| 20–80 | *(хоосон)* | — | хорих, солих, саатуулах, хуурах — **v1-д хоосон, N13 шалгана**. v3-ын Саатуулагч нь `docs/03` §3.2-ын каноноор **60 `BLOCK`** (GDD-02-ын «20» биш — 20 бол `JAIL`) |
| 90 | `protect` | **Эмч** | `grantedDefense[t] = basic` |
| 100 | `attack` | **Мафи** | довтолгоог **зарлана**, хэрэгжүүлэхгүй |
| 110 | *(хоосон)* | — | хариу цохилт (v2 Хамгаалагч) |
| 120 | `deathApply` | — | хөлдөөсөн snapshot-оор үхлийг хэрэгжүүлнэ |
| 130 | `info` | **Мөрдөгч** | шалгалтын үр дүн (§9.1-ийн preview-тэй тэнцэнэ) |
| **135** | `whisper` | **Иргэн + бүгд** | «Хотын шивнээ» — **манай шинэ хувин** |
| 140–150 | *(хоосон)* | — | 140 нь v2-ын «Өв»-д нөөцлөгдсөн. `recruit` (150) нь **үүрд хоосон** — гуравдагч тал байхгүй. |
| 160 | `messages` | — | мессеж ба `cues` угсрах |
| 170 | `winCheck` | — | `M ≥ T` / `M == 0` |

Хоёр хатуу дүрэм хүчинтэй хэвээр:

1. **Хувин нь зөвхөн өөрөөсөө ЧАНД доогуур хувингийн бичсэн төлөвийг уншина.** Дебаг билд дээр `_Work` классын setter-үүд одоогийн хувингийн дугаарыг шалгаад `assert` шиднэ (write-barrier).
2. **Хувин дотор** `rank(actor)` буюу `orderPerm`-ийн индексээр эрэмбэлнэ. **Илгээсэн хугацаагаар хэзээ ч биш.**

**135 яагаад 130-ын дараа вэ.** Шивнээ нь үхлийг (120) ба шалгалтыг (130) хоёуланг нь уншина: өнөө шөнө үхсэн суудал шивнээний сангаас **хасагдана**. Тиймээс тэр нь хоёуланаас дээгүүр байх ёстой. 131 биш 135 гэсэн нь `docs/03`-ын 10-ын завсрын конвенцийг эвдэхгүйн тулд — 140 нь «Өв»-д хэрэгтэй.

## 4. Мафи хэнийг алахаа хэрхэн шийдэх вэ

Жигд эргэлтийн дор мафи шөнө тохирч чадахгүй — гурван мафи гурван өөр суудалд, гурван өөр мөчид, тус тусдаа товшино. Тиймээс фракцийн дүрэм бол **тоглоомын дүрэм**, техникийн нарийн ширийн зүйл биш. Ширээ түүнийг сурах ёстой.

| N | `FactionRule` | Дүрэм |
|---|---|---|
| 8 (мафи 2) | `mafiaMajority` | Хамгийн олон товшилт авсан бай хожино |
| **10, 12, 16 (Ахлагчтай)** | **`designatedKiller`** | **Ахлагчийн товшилт хожино. Ахлагч хасагдсан бол `mafiaMajority` руу автоматаар унана.** |

```dart
/// Хэн шийдсэн (`actor`) ба хэн хохирсон (`target`) хоёрыг ХОЁУЛАНГ буцаана.
/// `actor` нь `Death.killer` ба `visits` дотор орно, тиймээс түүнийг таах БОЛОХГҮЙ.
({Seat actor, Seat target})? pickVictim(NightState s, List<Intent> kills) {
  if (s.setup.factionRule == FactionRule.designatedKiller) {
    final boss = s.aliveSeatWithRole(Role.boss);
    if (boss != null) {
      final k = kills.firstWhereOrNull((i) => i.actor == boss);
      if (k != null) return (actor: boss, target: k.target);   // Ахлагчийн үг = дүрэм
    }
  }
  // mafiaMajority: тоол, дараа нь ДЕТЕРМИНИСТ тэнцэл тайлалт
  final tally = <Seat, int>{};
  for (final k in kills) tally.update(k.target, (v) => v + 1, ifAbsent: () => 1);
  if (tally.isEmpty) return null;
  final best = tally.values.reduce(max);
  final tied = tally.keys.where((t) => tally[t] == best).toList()
      ..sort((a, b) => s.rank(a).compareTo(s.rank(b)));        // orderPerm, НЕ санамсаргүй
  final target = tied.first;                                   // TIEBREAK_SEEDED бүртгэгдэнэ
  final shooters = kills.where((i) => i.target == target).toList()
      ..sort((a, b) => s.rank(a.actor).compareTo(s.rank(b.actor)));
  return (actor: shooters.first.actor, target: target);        // rank хамгийн бага нь хутга барина
}
```

**Санамсаргүй тэнцэл тайлалт хориотой.** Wolfy тэнцэл дээр санамсаргүй нэгийг алдаг; тэр **мэдрэмжийг** авсан, гэхдээ `orderPerm`-ээр л. Шалтгаан нь: 15 настай хүүхэд «яагаад над руу явчихав?» гэж асуухад хариулт нь тоглолтын эхэнд бүртгэгдсэн, шалгаж болох сэлгэмэл байх ёстой.

**Ахлагч яагаад ялгарах вэ.** `00-vision` §6: «мафийн санал зөрөх мухардлыг дүрмээр биш, **эрх мэдлээр** шийднэ — хөтлөгч юу ч тайлбарлах шаардлагагүй.» Кодын хувьд энэ бол **6 мөр** ба нэг л дэлгэцийн шошго: Ахлагчийн үйлдлийн дэлгэцэн дээр «Чиний сонголт шийднэ.»

## 5. `resolveNight` — псевдо-код

Дуудагчийн `NightState`-ыг **хэзээ ч өөрчлөхгүй**. Дотроо `_Work` гэсэн хувирамтгай хуулбар барина, хувингуудыг доороос дээш дамжина, `NightReport` буцаана.

```dart
NightReport resolveNight(NightState s0, List<Intent> intents) {
  final w = _Work.from(s0);                                  // deep copy

  // ---- Лацдах: шалга, давхардлыг цэвэрл, бүрэн эрэмбэ тавь --------------
  var a = intents.where((i) => i.night == s0.night && validate(i, s0) == null)
                 .toList();
  a = dedupeKeepMaxClientSeq(a, by: (i) => (i.actor, i.ability));   // N19
  a.sort(byTuple([
    (i) => bucketOf(i.ability),
    (i) => s0.rank(i.actor),
    (i) => i.ability.index,
    (i) => i.intentId,                                       // тогтмол хугарал
  ]));
  w.inputHash = sha256(canon({'seed': s0.seed, 'night': s0.night, 'intents': a}));

  // ---- 90 protect --------------------------------------------------------
  for (final h in a.where((i) => i.ability == Ability.heal)) {
    w.grantedDefense[h.target] = DefenseLevel.basic;
    w.protectors.putIfAbsent(h.target, () => []).add(h.actor);
    w.visits.add(Visit(h.actor, h.target, Ability.heal, harmful: false));
    w.nextLastHeal[h.actor] = h.target;
  }

  // ---- 100 attack (ЗАРЛАНА, хэрэгжүүлэхгүй) ------------------------------
  final defSnapshot = Map.unmodifiable(w.effectiveDefense());  // P13: бүгд зэрэг буудна
  final kills = a.where((i) => i.ability == Ability.mafiaKill).toList();
  final hit = pickVictim(s0, kills);
  if (hit != null) {
    w.pending.add(Pending(hit.actor, hit.target, AttackLevel.basic, DeathTag.mafi));
    w.visits.add(Visit(hit.actor, hit.target, Ability.mafiaKill, harmful: true));
  }
  for (final k in kills) {                                    // хаягдсан товшилтууд ч
    w.whisperTally.bump(k.target);                            // шивнээний санд орно
  }

  // ---- 120 deathApply ----------------------------------------------------
  for (final p in w.pending) {                                 // v1: 0 эсвэл 1 элемент
    if (lethal(p.level, defSnapshot[p.to] ?? DefenseLevel.none)) {
      w.deaths.add(Death(p.to, p.from, p.tag));
      w.alive.remove(p.to);
    }
    // ЯМАР Ч хувийн мессеж байхгүй — §9.2-ыг үз
  }

  // ---- 130 info ----------------------------------------------------------
  for (final q in a.where((i) => i.ability == Ability.investigate)) {
    final m = infoAnswer(s0, q);                               // цэвэр, §9.1
    w.msgs.putIfAbsent(q.actor, () => []).add(m);
    w.visits.add(Visit(q.actor, q.target, Ability.investigate, harmful: false));
    w.whisperTally.bump(q.target);
  }

  // ---- 135 whisper -------------------------------------------------------
  for (final t in a.where((i) => i.ability == Ability.suspect)) {
    w.whisperTally.bump(t.target);
    // ЗОЧЛОЛ БИЧИГДЭХГҮЙ. Инвариант N17 (GDD-02 §4.2): сэжиглэх товшилт нь
    // зочлол БИШ — эс бөгөөс v2-ын Ажиглагч шөнө бүр бүгдийг харж, дүр өөрөө үхнэ.
  }
  for (final h in a.where((i) => i.ability == Ability.heal)) w.whisperTally.bump(h.target);
  if (s0.setup.whisperOn) w.whisper = topWhisper(w.whisperTally, w.alive, s0);

  // ---- 160 messages + cues ----------------------------------------------
  w.cues = buildCues(w);                                       // §9.3, чимээгүй нь дотор

  // ---- 170 winCheck ------------------------------------------------------
  w.win = evaluateWin(w);

  final r = w.toReport();
  assert(allInvariants(s0, a, r));                             // дебаг билд дээр
  return r;
}

List<Seat> topWhisper(Tally t, Set<Seat> aliveAfter, NightState s) {
  final pool = t.entries
      .where((e) => aliveAfter.contains(e.key))                // өнөө шөнө үхсэн нь хасагдана
      .where((e) => e.value >= s.setup.whisperMinAgree)        // анхдагч 3
      .toList()
      ..sort((x, y) {                                          // тоо буурахаар, дараа rank
        final c = y.value.compareTo(x.value);
        return c != 0 ? c : s.rank(x.key).compareTo(s.rank(y.key));
      });
  return pool.take(2).map((e) => e.key).toList()..sort();      // СУУДЛЫН ДУГААРААР өсөхөөр
}
```

**Гол санааг монголоор:** довтолгоо 100-д зөвхөн **зарлагдана**, 120-д л **хэрэгжинэ**, хамгаалалтын snapshot нь 100-д **хөлдөнө**. Ингэснээр «хэн хэнийг түрүүлж буудсан бэ?» гэсэн асуулт огт үүсэхгүй. v1-д довтолгоо нэг л байдаг тул энэ нь илүүц юм шиг харагдана — гэвч snapshot-ын хэлбэрийг одоо барих нь v2-д Манаач нэмэхэд хөдөлгүүрийг дахин бичихээс хамгаална.

**Шивнээний эрэмбэ хоёр давхар байгааг анзаар:** аль хоёр суудал гарахыг **тоогоор** шийднэ (rank нь зөвхөн тэнцэл тайлна), харин **хэвлэх дарааллыг суудлын дугаараар** шийднэ. Хоёр дахь эрэмбэ нь зориудын: «гурав, ес» гэсэн мөр аль нь илүү товшигдсоныг **хэлэхгүй**. Хөтлөгч тоог хэзээ ч уншихгүй.

> **Нэг маркчилсан зөрчил `00-vision` §4-тэй.** Тэнд «Иргэдийн шөнийн товшилт нь **механикийн хувьд хоосон**» гэж бичсэн. Энэ хөдөлгүүрийн дор тэр нь үнэн биш: `whisperMinAgree = 3` нь 12 суудалд мафийн тоотой тэнцүү тул **мафи өдөр тохиролцоод шивнээг хуурамчаар үүсгэж чадна**. Би үүнийг зориуд ингэж үлдээж байна — хоосон механик нь ширээнд хэрэггүй, харин «мафи шивнээг үйлдвэрлэж чадна» гэдэг нь өдрийн хэлэлцүүлэгт нэмэлт давхарга нэмнэ. Хэрэв ангид хэт хүчтэй болж хэмжигдвэл тохируулга нь **нэг бүхэл тоо** («Нээлттэй асуулт» №1).

## 6. Үйл явдлын бүртгэл

Нэг тоглолт = зөвхөн нэмэгддэг (append-only) мөрүүд. **Хүснэгт нь GDD-12 §2-ын `game_event`**, багана ба нэршил нь тэндээс. *(Энэ бүлэг өмнө нь өөрийн `event(seq, game_id TEXT, kind TEXT, payload TEXT)` хүснэгт ба PascalCase нэрс тодорхойлж байсан. GDD-12 §0 нь хадгалалтыг эвлэрүүлэх үүрэгтэй бөгөөд `type`-ыг «үүрд хөлдсөн текст» гэж зарласан — хоёр хүснэгт, хоёр нэршил зэрэг оршиж чадахгүй.)*

Хөдөлгүүрийн шаарддаг үйл явдлууд, GDD-12-ын `type` нэрээр:

| `type` | Агуулга |
|---|---|
| `GAME_CREATED` | `{n, setupId, orderPerm[], b0}` + `game.seed0_hex`, `deal_id` |
| `DEAL_DONE` | `{}` — **дүр бичигдэхгүй** (GDD-12 §4.2) |
| `PHASE_ENTERED` | `{"kind":"NIGHT","no":3}` |
| **`INTENT_SUBMITTED`** | `{intentId, night, actor, ability, target, clientSeq}` — **GDD-12-д нэмэгдэх шинэ төрөл** |
| **`NIGHT_SEALED`** | `{night, inputHash}` — **GDD-12-д нэмэгдэх шинэ төрөл**; `resolveIdempotent`-ийн оролт |
| `NIGHT_RESOLVED` | `{night, resultHash, victim, whisper[]}` |
| `HANDS_COUNTED` | `{day, seat, hands}` |
| `PIN` | `{elapsed_ms, speaker_seat}` |
| `BEST_MOVE_SPOKEN` | `{"n":3}` — **дугаарууд бичигдэхгүй** (GDD-12 §3; тиймээс энэ бүлгийн хуучин `seats[3]` хасагдав) |
| `GAME_ENDED` | `{winner, nights, resultHash}` |

`INTENT_WITHDRAWN` нь v1-д **байхгүй** — «Буцах» товч нь цонх дуусаагүй байхад л ажилладаг тул бүртгэл хүрэхгүй.

**Хамгийн чухал хэрэгжүүлэлтийн дүрэм:** `INTENT_SUBMITTED` нь **«Ширээн дээр тавь. Дараах — №8» гэсэн дэлгэц рендерлэгдэхээс өмнө**, `await commit(...)`-оор синхроноор бичигдэнэ (GDD-12-ын `no-paint-before-commit`). Хэрэв утас 8-р суудлын гар дээр унтарвал, дахин нээхэд бүртгэлд долоон санаа байгаа тул апп **8-р суудлаас үргэлжилнэ**. Async бичээд дэлгэц урьдчилж явбал тэр суудал хоёр дахин товшино — шөнийн эргэлтэд энэ нь тоглоомыг эвдэнэ.

**Дүрийн хуваарилалт бүртгэлд ОРОХГҮЙ** тоглолт дуусах хүртэл; `game_seat.role` нь зөвхөн `closeGame()`-д бичигдэнэ (GDD-12 §4.2). `GAME_CREATED` дотор зөвхөн `fairness_code` (зургаан аравтын тоо) байна. Аппын файлыг ухаж үзсэн хөтлөгч юу ч олж чадахгүй — `docs/10` §3-ын тохиролцоошгүй дүрэм.

## 7. Seed, ChaCha20 ба шударга байдлын код

### 7.1 Кодын гарал

**Алгоритмыг GDD-10 §2 эзэмшинэ.** Тэр бүлэг протоколыг (commit–reveal, `readerSeat`, `redealCount`) эзэмшдэг бөгөөд домэйн тусгаарлалтын шошготой цорын ганц хувилбарыг бичсэн. Энд зөвхөн давтаж байна, зөрвөл **GDD-10 ялна**:

```
1. seed0      <- Random.secure().nextBytes(32)
2. h0         <- sha256(seed0)
3. fairCode   <- u32be(h0[0..4]) % 1000000, зургаан оронтой болгож 0 нэм
                  → «412-995» гэж 3+3 хэлбэрээр харуулна
4. dealId     <- hex(h0[4..8])                 // 8 hex, hash-аас гарна
5. readerSeat <- pickSeat(u16be(h0[8..10]), N, exclude: holderSeat)
6. Уншигч кодыг цаасан дээр бичнэ, дараа нь утсыг 2 сек сэгсэрнэ эсвэл 4 цифр шивнэ
              → userEntropy
7. seed       <- sha256(utf8("HOTUNTLAA/v1") ‖ hex(dealId) ‖ seed0 ‖ userEntropy)
```

*(Өмнө нь энд `seed <- sha256(seed0 ‖ shake ‖ utf8(dealId))` ба `dealId <- "$gameId:$n:$dealCounter"` гэж бичигдсэн байв. Баримт бичигт seed-ийн **гурван** өөр томьёо, `dealId`-ийн **хоёр** өөр тодорхойлолт байсан бөгөөд GDD-12 §4.2-ын сэргээлт ба GDD-10 §10-ын `deal_golden_test` хоёулаа нэг л томьёоноос хамаарна.)*

**Зургаан аравтын тоо ≈ 20 бит. Хэн ч «хангалтгүй» гэж хэлэх болов уу — үгүй.** Халдагч бол ангийн хүүхэд, GPU биш. Амлалт нь зөвхөн нэг зүйлээс хамгаалах ёстой: **хөтлөгч мафи болтлоо дахин дахин хуваарилах.** Код нь хуваарилахаас **өмнө** цаасан дээр байгаа тул дахин хуваарилвал код таарахгүй. Дээрээс нь seed нь хөтлөгчийн хяналтгүй хоёр дахь эх сурвалжтай (сэгсрэлт). Аравтын тоо гэж сонгосон нь: зургаан hex тэмдэгтийг («a3f0c1») монголоор чангаар уншихад анги гацна, «дөрөв, нэг, хоёр — ес, ес, тав» гэдэг нь гацахгүй. **Энэ аргумент баримт бичгийн хамгийн хүчтэй нь тул 3+3 аравтын хэлбэр ялав**; GDD-06 S04-ийн «7F2A91» ба GDD-10 §3-ын «04 21 73» хоёр GDD-15-аар засагдав.

### 7.2 RNG

```dart
class Rng {                          // ChaCha20, nonce = 0, counter = 0-ээс
  Rng(Uint8List key32);
  int nextU32();
  int below(int bound) {              // rejection sampling — modulo хазайлт БАЙХГҮЙ
    final limit = 0x100000000 - (0x100000000 % bound);
    int x;
    do { x = nextU32(); } while (x >= limit);
    return x % bound;
  }
}
```

**Яагаад ChaCha20, splitmix64 биш.** 20 суудлын хуваарилалт бол `20! ≈ 2.4×10¹⁸` = **62 бит** — splitmix64-ийн 64 битийн төлөвт нүцгэн багтана. 256 битийн key нь төлвийг хэзээ ч хязгаарлагч хүчин зүйл болгохгүй. Хэрэгжүүлэлт нь ~60 мөр, RFC 8439-ийн тест векторуудаар шалгагдана — тэр тест нь `flutter test`-ийн хамгийн хямд, хамгийн үнэ цэнтэй файл.

**Хоёр урсгал, домэйн тусгаарлалттай:**

```dart
final deal  = Rng(sha256(concat(seed, utf8('DEAL'))));
final order = Rng(sha256(concat(seed, utf8('ORDER'))));
final roles = fisherYates(canonicalDeck(setup), deal);   // буурах давталт, below() ашиглана
final orderPerm = fisherYates(seatsAscending(n), order);
```

`orderPerm`-ыг тусдаа урсгалаас гаргах нь **инженерийн шийдвэр биш, аюулгүй байдлын шийдвэр**: `orderPerm` нь `GameCreated`-д ил бичигдэнэ. Нэг урсгалаас дараалан гаргавал ил байгаа сэлгэмэл нь нуугдмал хуваарилалтын тухай мэдээлэл өгнө.

### 7.3 Тоглолтын дараах шалгагч

Хамгийн сүүлийн дэлгэцүүдийн нэг: **«Шударга байдлын шалгалт»**. Харуулах зүйл: `seed0` (hex), `shake` (hex), `dealId`, `seed` (hex), кодыг дахин бодсон нь, ба хуваарилалтыг дахин гаргасан нь.

> **«Дэвтэр дээрх кодтой ижил байна уу?»**
> «Аппын код: **412-995**»
> «Дахин хуваарилахад: 1-Иргэн, 2-Ахлагч, 3-Иргэн…»

**Апп «Таарлаа» гэж ХЭЗЭЭ Ч хэлэхгүй** (GDD-10 §3, §9.5): өөрийгөө өөрөө батлах эрх аппад байхгүй. Дэлгэц зөвхөн тоог гаргана, харьцуулалтыг дэвтэр барьсан хүн хийнэ.

Энэ дэлгэц нь «Хөзрөө нээе»-ийн **дараа** гарна, тусдаа товчны цаана. Хэн ч харахгүй байж болно — гол нь **харж болдог** гэдэг нь.

## 8. Идемпотент дахин шийдвэрлэлт

Офлайн нэг утсан дээр хамгийн бодит эвдрэл бол: шөнийн эргэлтийн дундуур апп үхэх (MIUI-ийн батерейны менежер), эсвэл шийдвэрлэсний дараа дэлгэц зурагдахаас өмнө үхэх.

```dart
NightReport resolveIdempotent(Store st, NightState s, List<Intent> sealed) {
  final h = sha256(canon({'seed': s.seed, 'night': s.night, 'intents': sortSealed(sealed)}));
  final cached = st.nightResolved(s.night);      // game_event-ийн NIGHT_RESOLVED мөр
  if (cached != null) {
    if (cached.inputHash == h) return cached.report;          // дахин тооцоолохгүй
    throw EngineStateCorrupt(s.night, cached.inputHash, h);   // ЧИМЭЭГҮЙХЭН БҮҮ ЗАС
  }
  final r = resolveNight(s, sealed);
  st.putNightResultIfAbsent(s.night, h, r);                   // нэг бичигч, CAS
  return st.nightResult(s.night)!.report;
}
```

**`EngineStateCorrupt`-ыг чимээгүйхэн засах нь хамгийн хортой алдаа байх болно.** Хэрэв `inputHash` зөрвөл өгөгдлийн сан ба бүртгэл зөрчилдсөн гэсэн үг. Тэр үед хийх зөв зүйл нь: `GameCreated`-аас эхлээд бүх `IntentSubmitted`-ыг дахин тоглуулж, шөнө бүрийг дахин шийдвэрлэж, `resultHash`-уудыг харьцуулах. Дэлгэц: **«Тоглолтыг эхнээс нь дахин уншиж байна.»** ~1 секунд, 20 суудал, 10 шөнө.

**Гурван кэшийн давхарга, тодорхой:**

| Давхарга | Хаана | Хэзээ бичигдэнэ |
|---|---|---|
| `game_event` (GDD-12 §2) | `angi.sqlite` | суудал товших мөчид, `await commit(...)`-оор |
| `NIGHT_RESOLVED`-ийн `payload_json` (`input_hash`, `result_hash`) | ижил хүснэгт | лацдсаны дараа, нэг л удаа |
| `NightReport` объект | RAM | дэлгэц зурахад |

*(Өмнө нь энд `night_result(night PK, input_hash, report_json)` гэсэн **тусдаа хүснэгт** байсан бөгөөд GDD-12-ын схемд байдаггүй. Нэмэлт хүснэгт хэрэггүй: `NIGHT_RESOLVED` мөр нь `input_hash`-ыг аль хэдийн үүрч чадна, бөгөөд `rebuild()` түүнийг `seq`-ээр олно.)*

Дахин нээхэд апп **үргэлж** `game_event`-ээс `NightState`-ыг дахин барина. RAM-д хадгалсан зүйлд хэзээ ч итгэхгүй.

## 9. Мессеж, дохио ба тооны самбар

### 9.1 Мөрдөгчийн хариу — товших мөчид

v1-д хуурах дүр **байхгүй** тул `investigate` нь хуваарилалтын цэвэр функц болно:

```dart
Msg infoAnswer(NightState s, Intent q) =>
    factionOf(s.setup.roleBySeat[q.target]!) == Faction.mafi
        ? Msg(MsgCode.traceFound)          // «Мөр олдлоо.»
        : Msg(MsgCode.traceNotFound);      // «Мөр олдсонгүй.»
```

Энэ функц шөнийн бусад ямар ч үйлдлээс хамаарахгүй. Тиймээс **үйлдлийн дэлгэц хариуг тэр дор нь харуулж болно** — Мөрдөгч товшино, 2.0 секунд «Мөр олдлоо» гарна, дэлгэц арчигдана, утас дараагийн суудал руу явна. `resolveNight` нь 130-р хувинд **яг тэр функцийг дахин дуудаж** тайланд бичнэ; хоёр хариу зөрвөл инвариант N21 унана.

**Энэ ганц дүгнэлт юуг устгав:** үүрийн хувийн дэлгэцийн давхарга, «утсыг дахин дамжуул» гэсэн хоёр дахь эргэлт, ~8 хөгжүүлэлтийн цаг. Ахлагч нь **шалгалтаас далдлагдахгүй** — v1-д ямар ч дүр хуурамч талтай биш (3-р багана: хөтлөгч худлаа хэлэхгүй).

### 9.2 Яагаад өөр хувийн мессеж БАЙХГҮЙ вэ

`docs/03` §3.8 нь зургаан мессежийн код жагсаасан. v1-д зөвхөн хоёр л гарна. Үлдсэнийг **баталгаатайгаар** хасч болно:

| Хасагдсан мессеж | Яагаад хэрэггүй вэ |
|---|---|
| `YOU_HEALED_SOMEONE` | **Баталгаа нь татагдсан, шийдвэр нь хэвээр.** §1-ийн 1-р дүрэм `noAction`-ыг зөвшөөрснөөр «мафи шөнө бүр заавал нэгийг оносон» гэдэг нь **үнэн биш** болсон: `DAWN_NO_KILL` нь одоо *эсвэл* Эмч аварсан, *эсвэл* нэг ч мафи товшоогүй гэсэн хоёрдмол мөр. **Тэр хоёрдмол байдал нь зориудын үр дүн** — 4-р татгалзал («хөтлөгч мэдээлэл зарахгүй») түүнийг шаарддаг, бөгөөд Эмчид «аварлаа» гэж хэлэх нь түүнийг эхний шөнөдөө баталгаат дүр болгоно. Тиймээс мессеж нэмэгдэхгүй, харин **аргумент нь «баталгаатай илүүц» гэдгээс «зориуд хоёрдмол» болж өөрчлөгдөв**. |

| `ROLEBLOCKED`, `JAILED_NO_ACTION` | Саатуулагч, Шоронгийн дарга v1-д байхгүй |
| `FACTION_TARGET_OVERRIDDEN` | Мафи Ахлагч шийддэгийг мэднэ. Дэлгэцийн шошго нь хангалттай. |

### 9.4 Тооны самбар ба ялалт

```dart
int b0(int n, int m) => (n ~/ 2) - m - 1;                 // 12, 3 → 2
int pipsForDay(int n, int m, int dayIndex) => b0(n, m) - (dayIndex - 1);

WinState evaluateWin(_Work w) {
  final m = w.alive.where((s) => w.factionOf(s) == Faction.mafi).length;
  final t = w.alive.length - m;
  if (m == 0) return WinState.hotynhon;
  if (m >= t) return WinState.mafi;                        // шөнө-эхэлдэг конвенц
  return WinState.none;
}
```

**`pipsForDay` нь дүрийг хэзээ ч уншихгүй — зөвхөн `n`, `m` ба өдрийн дугаарыг уншина.** Энэ бол **шийдвэр, оновчлол биш**. Хэрэв «алдаж болох санал»-ыг буруу санал болсон үед л хасвал ● ● → ● болох нь **хасагдсан хүн хотынхон байсныг зарлана**, тэр нь `00-vision` §11-ийн «хасагдахад дүр нээгдэхгүй» татгалзлыг апп өөрөө зөрчсөн болно. Өдрийн дугаараар хасах нь консерватив (зөв санал өгсөн өдөр ч хасагдана) бөгөөд **алдагдал тэг** — ширээ ямар ч байсан хамгийн хүнд хувилбарыг харж байна.

`b₀ = ⌊N/2⌋ − M − 1` нь `docs/04` §2.3-т N = 4…60 хүртэл бүрэн хайлтаар шалгагдсан. Түүнийг **тест болгон repo-д commit хийнэ** (§10-ын P7). Тохиргоонд `b₀ < 0` бол **хатуу татгалзал**: «Энэ бүрэлдэхүүнээр мафи эхний шөнөдөө яллаа. Тоглогч нэм эсвэл мафи хас.»

### 10.3 Fuzz харнесс

```dart
void main() {
  final n0 = int.parse(Platform.environment['FUZZ_SEEDS'] ?? '2000');
  for (var seed = 0; seed < n0; seed++) {
    final rng   = Rng(sha256(utf8.encode('fuzz:$seed')));
    final n     = 4 + rng.below(19);                     // 4..22 — хууль бус хязгаар ч турших

    var state   = newGame(n, rng);                       // хууль бус бүрэлдэхүүн ч үүснэ

      assert(resolveIdempotent(mem, state, intents).resultHash == r.resultHash);

    }

}
```

**Бодит хуваарь, оюутны чадвараар:** `flutter test`-ийн дотор **2,000 seed** (< 10 секунд, PR бүрд). `dart tool/fuzz.dart` нь **200,000 seed** (~3 минут зөөврийн компьютер дээр), **хаалга бүрийн өмнө нэг удаа** ажиллана. `docs/03`-ын «шөнө бүр 1 сая seed» гэсэн зөвлөмж нь CI дэд бүтэц шаардана — энэ төсөлд түүнийг **хасаж байна**, орондоо хоёр бодит тоог барьж байна. **GDD-13 §4.2 энэ хуваарийг авсан** (өмнө нь тэнд «PR тутам 10,000 / шөнө тутам 1,000,000» гэж бичигдсэн байсан бөгөөд энэ бүлэгтэй шууд зөрчилдөж байв); `FUZZ_SEEDS`-ийн анхдагч нь хоёр газарт нэг `const`-оос уншигдана.

Нэмэлт хоёр зүйл, хямд бөгөөд их үнэ цэнтэй:

- **Golden snapshot.** **Есөн** тогтоосон шөнө — жагсаалт нь **GDD-13 §4.3-ын fixture хүснэгт** (энэ бүлэг өмнө нь 12 гэж бичдэг байв; хоёр тоо, нэг хавтас). Хүлээгдэж буй `NightReport`-ын canonical JSON нь repo-д commit хийгдэнэ. Шийдвэр чимээгүйхэн өөрчлөгдвөл diff гарна. **~0.5 өдөр, бүх багцын хамгийн өндөр өгөөжтэй тест.**
- **Дифференциал тест.** `resolveNightNaive` — гэнэн, 40 мөрийн, оновчлолгүй хэрэгжүүлэлт. Fuzz тохиолдол бүр дээр хоёрыг харьцуулна. v1-ийн хөдөлгүүр өөрөө бага зэрэг оновчлогдсон тул энэ нь **v2-т** хэрэгтэй болно — одоо бичихгүй.

## 11. Бодит жишээ — 12 тоглогч, 2-р шөнө, алхам алхмаар

**Бүрэлдэхүүн `MN_12`:** 3 мафи (P2 **Ахлагч**, P5 Алуурчин, P11 Алуурчин), P4 **Эмч**, P9 **Мөрдөгч**, P1·P3·P6·P7·P8·P10·P12 **Иргэн**. `b₀ = ⌊12/2⌋ − 3 − 1 = **2**`.

`seed`-ээс `orderPerm = [9, 4, 12, 1, 11, 6, 2, 8, 5, 10, 3, 7]` → `rank(P9)=0`, `rank(P4)=1`, `rank(P12)=2`, `rank(P1)=3`, `rank(P11)=4`, `rank(P6)=5`, `rank(P2)=6`, `rank(P8)=7`, `rank(P5)=8`, `rank(P10)=9`.

Өмнөх түүх: **1-р шөнө P7 хохирсон**, **1-р өдөр P3 хотоос хөөгдсөн**. Амьд **10**: P1 P2 P4 P5 P6 P8 P9 P10 P11 P12. M = 3, T = 7. `lastHealTarget[P4] = P6`.

| Суудал | Дүр | `ability` | Бай |
|---|---|---|---|
| P1 | Иргэн | `suspect` | 5 |
| P2 | **Ахлагч** | `mafiaKill` | **9** |
| P4 | Эмч | `heal` | **9** |
| P5 | Алуурчин | `mafiaKill` | 4 |
| P6 | Иргэн | `suspect` | 5 |

**Шийдвэрлэлт:**

1. **Лацдах.** 10 санаа бүгд шалгалтыг давна. P4-ийн `heal → 9` нь `healRepeat`-д унахгүй (өчигдөр 6 байсан). `dedupe` юу ч хасахгүй. Бүрэн эрэмбэ: `heal(P4)` → `mafiaKill(P2, P5, P11 — rank 6, 8, 4 тул P11, P2, P5)` → `investigate(P9)` → `suspect(P1, P6, P8, P10, P12)`. `inputHash = sha256(canon(...))`.
2. **90 `protect`.** `grantedDefense[9] = basic`. `protectors[9] = [4]`. Ирмэг P4→P9.
3. **100 `attack`.** `defSnapshot = {9: basic, бусад: none}` — **хөлдлөө**. `designatedKiller`: Ахлагч P2 амьд, түүний бай **9**. P5 (бай 4) ба P11 (бай 9) хаягдана, ямар ч мессеж илгээгдэхгүй. `pickVictim` нь `(actor: 2, target: 9)` буцаана — P11 мөн 9-ийг товшсон ба `rank(P11)=4 < rank(P2)=6` боловч `designatedKiller` салаа нь `rank`-ыг огт уншихгүй. `pending = [{from: 2, to: 9, basic, mafi}]`. Ирмэг P2→P9 (хортой).
4. **120 `deathApply`.** `lethal(basic=1, basic=1)` → `1 > 1` **хуурамч**. **P9 амьд.** `deaths = []`. **Хувийн мессеж байхгүй** — P9 юу ч мэдэхгүй, P4 юу ч мэдэхгүй.
5. **130 `info`.** P9 нь P11-ийг шалгана. P11 = Алуурчин → `Faction.mafi` → **«Мөр олдлоо.»** Энэ мөр нь P9-ийн гарт, эргэлтийн дундуур **аль хэдийн харагдсан**; хувин нь зөвхөн тайланд бичээд `assert` хийнэ (N21).
6. **135 `whisper`.** Суудал бүрийн **цорын ганц санааны бай** тоологдоно (тусдаа шивнээний товшилт байхгүй — §5). Сан: **5 → 3** (P1, P6, P10) · **9 → 3** (P2-ийн алалт, P4-ийн эдгээлт, P11-ийн хаягдсан алалт) · **2 → 2** (P8, P12) · **4 → 1** (P5) · **11 → 1** (P9). Өнөө шөнө хэн ч үхээгүй тул хасалт байхгүй. Босго = 3 → `{5: 3, 9: 3}`. Тэнцэл: `rank(P9)=0 < rank(P5)=8`, тиймээс хоёулаа сонгогдоно. Хэвлэх нь **суудлын дугаараар**: **`whisper = [5, 9]`**.
7. **160 `cues`.** `[line DAWN_NO_KILL, line WHISPER, screenSeats(5, 9)]`. Үхэл байхгүй тул 2.5 секундын блок байхгүй.
8. **170 `winCheck`.** M = 3, T = 7 → `WinState.none`.

**Ширээ юу сонсох вэ:**

> «Хот сэрлээ. Бүгд нүдээ нээ.»
> **«Өнөө шөнө хохирогч гарсангүй.»** (`DAWN_NO_KILL`)
> **«Хот шивнэж байна.»** (`WHISPER`) — дэлгэц дээр: **«Шивнээ: 5 · 9»**, ширээнээс хэн нэг нь чангаар уншина

Дараа нь дэлгэц: **2-р өдөр · «Алдаж болох санал: ●»** (`pipsForDay(12, 3, 2) = 2 − 1 = 1`).

**Өрөөнд юу болов гэдгийг тоогоор:** мафи P9 Мөрдөгчийг оносон, Эмч сохроор яг тэр суудлыг аварсан, шивнээ нь Мөрдөгчийн дугаарыг нийтэлсэн (учир нь мафийн хоёр товшилт + Эмчийн товшилт), бөгөөд **хэн ч үүнийг мэдэхгүй**. P9 одоо гартаа «P11 мафи» гэсэн мэдээлэлтэй, харин өөрөө шивнэгдсэн тул сэжигтэй. Апп нэг ч худал үг хэлээгүй, нэг ч оноо тавиагүй. `resultHash` бүртгэлд орж, дахин холбогдоход яг энэ үр дүн буцна.

## Нээлттэй асуулт

1. **`whisperMinAgree = 3` уу, 4 уу?** 12 суудалд 3 нь мафийн тоотой тэнцүү тул мафи өдөр тохиролцоод гурван товшилтоор гэмгүй хүнийг шивнүүлж чадна. **Хэмжих нь:** таван суултад шивнээ хэдэн удаа нийтлэгдэв, хэдэн удаа **хожим мафи байсан хүн** шивнэгдсэн бэ (дэвтэрээс тоолж болно). Хэрэв шивнээ нь мафийн зэвсэг болж хэмжигдвэл **4 болго** — нэг бүхэл тоо, дахин бичих код байхгүй.
2. **Эмчийн «аварлаа» мессежийг үнэхээр хасах нь зөв үү?** §9.2-ын баталгаа логикийн хувьд бат, гэвч 15 настай Эмч нийтийн мөрнөөс дүгнэлт гаргах уу? **Хэмжих нь:** тоглолтын дараа Эмчийг тоглосон хүүхдээс *«Өчигдөр чиний аврал ажилласан гэдгийг мэдэв үү?»* гэж асуу. Гурван суултаас хоёрт «мэдээгүй» гэвэл `MSG.HEAL_WORKED`-ыг нэмнэ — гэхдээ тэр нь **үүрийн хувийн дэлгэц** шаардана, ~1.5 өдөр, бөгөөд §9.1-ийн бүх хэмнэлтийг буцааж авна. Тиймээс энэ асуултын хариу нь v1-ийн хамрах хүрээг шийднэ.
3. **`healRepeat` дүрэм ширээнд ойлгогдож байна уу?** «Өчигдөр аварсан хүнээ дахин аварч болохгүй» гэсэн дүрмийг Эмч сурах ёстой, бөгөөд хөтлөгч түүнийг тайлбарлахгүй. Хэрэв гурван суултад Эмч гурав удаа татгалзлын дэлгэц харвал дүрмийг **хаяж** тавь — тэнцвэрт нөлөө нь 04 §0.6-аар ≈0.
4. **`EngineStateCorrupt` бодитоор хэд гарах вэ?** Зээлсэн Redmi ба Huawei дээр шөнийн эргэлтийн дундуур апп үхэх нь **үндсэн тохиолдол**, захын тохиолдол биш. **Хэмжих нь:** M2.5-д эргэлтийн дундуур утсыг 10 удаа хүчээр хаа. Хэрэв бүтэн дахин тоглуулалт 1 секундээс их болвол `NIGHT_RESOLVED`-ийн кэшлэгдсэн `result_hash`-ыг заавал ашигла; хэрэв `inputHash` зөрөх нь илэрвэл `INTENT_SUBMITTED`-ын `commit()` синхрон биш байна гэсэн үг.
5. **`AttackLevel.powerful`-ыг enum дотор одоо байлгах нь зөв үү?** N13 нь v1-д хэрэглэгдэхгүйг шалгана, тиймээс зардал нь тэг. Гэвч хэрэв v2 хэзээ ч ирэхгүй бол энэ нь уншигчийг төөрөгдүүлэх хоосон код. **Шийдвэр:** байлга. Хасах нь 5 минут, дараа нь нэмэх нь `lethal`-ын бүх тестийг дахин бичих.
6. **Дүрийн хуваарилалтыг RAM-д барих уу, шифрлэж хадгалах уу?** `docs/10` §3 хоёуланг зөвшөөрдөг. **Анхдагчаар ачаалж байгаа нь: зөвхөн RAM.** Хэрэв асуулт 4-ийн хэмжилт нь апп шөнө бүр үхдэг гэж гаргавал хуваарилалтыг хадгалах хэрэгтэй болно — тэр үед `seed0`-г SQLite-д хадгалаад хуваарилалтыг дахин гаргах нь хамгийн хямд (шифрлэлт огт хэрэггүй, учир нь `seed0` нь `shake`-гүйгээр хуваарилалтыг гаргаж чадахгүй).
