# GDD-12 — Өгөгдлийн модель, хадгалалт ба сэргээлт

> **Шийдвэрийн хураангуй**
> - **Нэг л дэлгүүр: `getApplicationSupportDirectory()/angi.sqlite`, `drift`-ээр.** 13 §8-ийн `game_state.json` **устана**, 03 §6-ийн «`sqflite` хоёр хүснэгт» нь ижил хоёр хүснэгт хэвээр, зөвхөн drift үүсгэнэ. Хоёр дэлгүүр = хоёр үнэн = ангийн дэвтэр залгидаг алдаа.
> - **`game_event` бол шинэ хүснэгт ба цорын ганц үнэн.** Зөвхөн нэмэгдэнэ. Дэвтрийн хуудсууд (09-ийн 7 хүснэгт) нь түүнээс **дахин бүтээгддэг** проекц.
> - **`no-paint-before-commit`.** Атом үйлдэл бүр нэг транзакц; `await` эргэж ирсний **дараа** л дэлгэц зурагдана, аудио тоглоно. WAL + `synchronous=FULL` — батерей дуусахад хамгийн сүүлийн **нэг** үйлдэл л алдагдана, 13 §8-ийн «үе шатны зааг» биш.
> - **Дүр дискэнд тоглолтын дунд бичигдэхгүй.** `game.seed0 + shake + deal_id` хадгалагдана, сэргээлт нь тараалтыг **дахин гаргана**. `game_seat.role` нь зөвхөн `closeGame()`-д бичигдэнэ. 10 §4-ийн нууцлалын дүрэм ба 13-ийн C2 хоёулаа хангагдана.
> - **Сэргээлт мэдээллийг хэзээ ч дахин харуулахгүй:** хөзрийг дахин нээхгүй, товшилтоо хийсэн суудлыг дахин асуухгүй. Алдагдсан 6 секунд нь алдагдсан нууцаас зуу дахин хямд.
> - **Нэг тоглолт ≈ 22 КБ** (дэвтрийн 1.5 КБ + бүртгэлийн ~20 КБ). **Бүртгэл сүүлийн 20 тоглолтод бүтнээр** үлдэнэ — 09-ийн `pin_mark`/`whisper_tap`-ийн цонхтой **яг ижил тоо**. Толгой мөр ба дүрийн хүснэгт үүрд.
> - **Экспортод `game_event` орохгүй.** Түүхий товшилт ангид зэвсэг болно; `angi-YYYY-MM-DD.json` нь зөвхөн дэвтэр.
> - **`allowBackup="false"`, `INTERNET` мөр огт байхгүй** → Play Data safety **«Ямар ч өгөгдөл цуглуулдаггүй»** нь үгчилсэн үнэн.

*Хамаарал: 00 §3 (4-р багана), §8 · 03 §6 (config blob) · 05 §7 (тараалт) · 09 (дэвтрийн схем) · 10 §4 (дүрийн нууцлал) · 13 §8 (C1–C8).*

## 1. Хөдөлгүүр, файл, PRAGMA

| Шийдвэр | Юу вэ | Яагаад |
|---|---|---|
| Сан | **`drift`**, схем нь **`lib/data/schema.drift`** дотор жинхэнэ SQL | Баримт бичиг нь схем өөрөө; 09 §5-ийн `migration_test.dart` аль хэдийн drift дээр. |
| Файл | `getApplicationSupportDirectory()/angi.sqlite` | 09 §1. Кэш биш — кэш цэвэрлэгддэг. |
| Диалект | **SQLite 3.9 шал** (`minSdk 24` = Android 7.0) | `UPSERT`, `json_extract`, цонхны функц, `DROP COLUMN` — **байхгүй гэж үз.** JSON-ыг зөвхөн Dart-д унш. |
| `shared_preferences` | **Зөвхөн хоёр зүйл:** сэдэв, дууны түвшин (09 §1) | Дүрэм: **сэргээлтийн замд хэрэгтэй ямар ч зүйл тэнд байж болохгүй.** |

```dart
// AppDb.beforeOpen — дарааллыг бүү сольж бич
await customStatement('PRAGMA journal_mode = WAL');
await customStatement('PRAGMA synchronous = FULL');   // §3-ийн батерейн шийдвэр
await customStatement('PRAGMA foreign_keys = ON');
await customStatement('PRAGMA busy_timeout = 3000');
```

`synchronous=FULL` нь commit тутамд WAL-ыг fsync хийнэ; бичилт frame дотор биш тул төлбөр тэвчихийн. **Зорилт: Redmi 9A дээр commit тутам < 25 мс.** `auto_vacuum=INCREMENTAL` нь **хоосон файл дээр**, хүснэгт үүсэхээс өмнө тавигдана.

## 2. Схем

09 §1-ийн долоон хүснэгт (`klass`, `seat`, `game`, `game_seat`, `pin_mark`, `whisper_tap`, `title_award`) ба 03 §6-ийн `class_config` **өөрчлөгдөхгүй**. GDD-12 нь дөрвөн хүснэгт нэмж, `game`-д сэргээлтийн баганууд оруулна.

```sql

   -- 'in_progress' | 'finished' | 'abandoned'   (09-ийн «дуусаагүй» шошго)

ALTER TABLE game ADD COLUMN deal_id      TEXT NOT NULL DEFAULT '';
```

`gap_after_ms` нь **GDD-07 §3-ын 27 мөрийн хүснэгтээс** үүсдэг (`narrator_timing.dart` → seed скрипт → `audio_clip`), гараар бичигдэхгүй. Гурав дахь хуулбар үүсгэх нь гурав дахь үнэн үүсгэнэ — тиймээс энэ багана бол **кэш**, эх сурвалж биш.

*(Хуучин тайлбар нь `NIGHT_KILL_A` гэсэн, GDD-07-ын каталогт байхгүй ID-г нэрлэж, эх сурвалжаар 00 §9 ба 13 §7-ыг заасан байв.)*

## 3. Үйл явдлын төрлүүд ба «атом үйлдэл бүрийн дараа хадгал»

`type` бол үүрд хөлдсөн текст. **Хуучин төрөл утгаа хэзээ ч сольдоггүй; шинэ утга = шинэ нэр.** Уншигч танихгүй төрлийг алгасаад тоолно.

| `type` | Хэзээ | `payload_json` |
|---|---|---|
| `GAME_CREATED` | Тохиргоо батлагдах | `{}` — дүрэм нь `config_json`-д |
| `SEED_COMMITTED` / `ENTROPY_ADDED` | Тараахын өмнө | `{"code":"412-995"}` / `{"src":"shake","seat":9}` |
| `DEAL_DONE` | Холилт бодогдох | `{}` — **дүр бичигдэхгүй** (§4.2) |
| `CARD_SEEN` / `CARD_RESEEN` | Хөзөр тавих / дахин нээх | `{"held_ms":2480}` / `{"n":2}` |
| `PHASE_ENTERED` | Үе шат солигдох | `{"kind":"NIGHT","no":3}` |
| `INTRO_NIGHT_DONE` | 60 сек дуусах | `{"actual_ms":60000}` |
| `INTENT_SUBMITTED` | Суудал товших (эсвэл цонх `noAction`-оор хаагдах) | `{"intent_id":"…","night":3,"ability":"mafiaKill"\|"heal"\|"investigate"\|"suspect"\|"noAction","client_seq":1}` + `actor_seat`, `target_seat`. **GDD-05 §6 үүнийг шаардана** |
| `NIGHT_SEALED` | Эргэлт дуусах | `{"night":3,"input_hash":"…"}` — `resolveIdempotent`-ийн оролт |
| `NIGHT_RESOLVED` | Үүрээр | `{"victim":7,"healed":null,"check":"FOUND","result_hash":"…"}` |
| `WHISPER_PUBLISHED` | Үүрээр | `{"seats":[3,10],"agree":[4,3]}` |
| `BEST_MOVE_SPOKEN` | Шилдэг нүүдэл | `{"n":3}` — **дугаарууд бичигдэхгүй** |
| `PIN` | 📌 дарагдах | `{"elapsed_ms":74000,"speaker_seat":5}` |
| `HANDS_COUNTED` | Гар тоолох | `{"hands":7}` |
| `EXILED` / `SEAT_OUT` | Хотоос хөөх / аль ч хасалт | `{}` / `{"cause":"NIGHT"\|"VOTE"}` |
| `PAUSED` / `RESUMED` | Дуудлага, хонх, ар тал | `{"reason":"CALL"\|"BACKGROUND"}` |
| `RESUMED_AFTER_KILL` | Сэргээлт | `{"gap_ms":184000,"lost_actions":1}` |
| `GAME_ENDED` / `ABANDONED` | Ялалт / «Цуцлах» | `{"winner":"TOWN","nights":5}` / `{"at":"D3"}` |
| `AUDIO_FALLBACK` | Клип тоглоогүй | `{"clip":"DAWN_VICTIM_07","reason":"PLAYER_DEAD"}` |

**`BUDGET_SPENT` хасагдав.** Тэр нь «Иргэн хасагдах» үед `{"b_left":1}` бичдэг байсан — өөрөөр хэлбэл **хасагдсан хүний талыг бүртгэлд бичдэг**. Тооны самбар нь GDD-05 §9.4-өөр **өдрийн дугаараар** буурдаг тул тоо нь `PHASE_ENTERED`-ээс гарна; тусад нь бичих нь дүрийн дүгнэлтийг `game_event`-д үүрд хадгалахтай тэнцэнэ.

**Атом үйлдэл** = ширээ түүнийг маргалдахгүйгээр дахин хийж чадахгүй ямар ч зүйл: хөзрөө харах, шөнийн товшилт, гар тоолох, 📌, үе шат солих. Frame, дууны эхлэл, анимац — атом биш.

```dart
// Бүх бичилт ЭНЭ ганц функцээр явна. Өөр замаар game_event-д бичих PR татгалзана.
Future<int> commit(GameEvent e) => db.transaction(() async {
  final s = await db.nextSeq(e.gameId);            // MAX(seq)+1, транзакц дотор
  await db.into(db.gameEvent).insert(e.row(s));
  await (db.update(db.game)..where((g) => g.id.equals(e.gameId)))
        .write(GameRow(resumeSeq: Value(s)));
  await applyProjection(e);        // game_seat / pin_mark / whisper_tap / game
  return s;
});                               // <-- дэлгэц ба аудио ЗӨВХӨН үүний дараа
```

**Код review-ийн дүрэм: `no-paint-before-commit`.** Үе шатыг урагшлуулдаг `setState`, `Navigator.push`, `player.play()` — гурвуулаа `await commit(...)`-ийн доор. Тест нь `commit`-ыг 500 мс саатуулж, дэлгэц хөдөлгөөнгүй байгааг шалгана.

**Хэлэлцүүлгийн цаг үйл явдал биш** — тэр урсаж байдаг. **5 секунд тутам** `game.live_clock_ms`-д бичигдэнэ; хамгийн муу алдагдал **5 секунд**. Сэргэхэд цагийг ханын цагаас **дахин бодохгүй** (13-ийн C3) — батерей гурван цаг унтарсан байж мэднэ.

## 4. Сэргээлтийн гэрээ

Хүйтэн эхлэхэд: `SELECT * FROM game WHERE state='in_progress' ORDER BY started_at DESC LIMIT 1`. Байвал нүүр хуудсын оронд:

> **«Дуусаагүй тоглоом байна.»** · «12 хүн · 3-р шөнө · 14 минутын өмнө»
> **«Үргэлжлүүлэх»** · «Цуцлах»

«Цуцлах» нь 09 §4-ийн дүрмээр ажиллана: мөр **устана**, цолны дараалал тасалдахгүй. Харин **апп унасан** тоглолт `state='in_progress'` хэвээр үлдэж, дэвтэрт «дуусаагүй» шошготой харагдана — апп өөрийнхөө алдааг нуухгүй.

| Хаана унасан | Сэргэх цэг | Юуг ХЭЗЭЭ Ч дахин хийхгүй | 13 §8 |
|---|---|---|---|
| Тохиргооны дунд | Тоглолт үүсээгүй; суудал хадгалагдсан | — | — |
| Тараалтын дунд | `card_seen` хийгээгүй хамгийн бага суудал | Дахин тараахгүй; дүр өөрчлөгдөхгүй | **C2** |
| Танилцах шөнийн 60 сек-д | Шөнө 0-ийн эхнээс, бүтэн 60 сек | — | — |
| Шөнийн эргэлтийн 7 дахь суудал | №7-ийн «утсаа өргө» дэлгэц | 1–6-ийн товшилтыг асуухгүй, харуулахгүй | **C1** |
| `NIGHT_RESOLVED`-ийн дараа | `DAWN_A`-аас бүтнээр | Шөнийг дахин бодохгүй; хохирогч бичигдсэн | — |
| Хэлэлцүүлгийн дунд | `live_clock_ms`-аас | Тэглэхгүй, ханын цагаар нэмэхгүй | **C3** |
| Гар тоолохын дунд | Тэр нэр дэвшигчийн дугуйнаас | Өмнөх нэр дэвшигчдийг дахин асуухгүй | — |
| «Хөзрөө нээе»-гийн дунд | Нээгээгүй хамгийн бага суудлаас | Нээгдсэнийг дахин нээхгүй | — |
| Ар тал → урд тал | **Заавал «дарж байж хар»** руу унана | Дүр илчлэгдсэн хэвээр үлдэхгүй | **C4** |

**Хамгийн чухал дүрэм:** сэргээлт мэдээллийг дахин **харуулахгүй**. №7 товшилтоо хийчихсэн бол апп «дахин батлаач» гэж асуухгүй — тэр асуулт өөрөө №7 юу хийснийг хажуугийнханд шивнэнэ.

### 4.1 Дахин бүтээлт

Дэвтрийн проекц (`game_seat`, `pin_mark`, `whisper_tap`, `game`-ийн нийлбэрүүд) эвдэрсэн байж магадгүй ямар ч сэжиг — хувилбар сольсон, миграц хийгдсэн, `unknown_event_count > 0` — дээр `rebuild(gameId)` нь тэднийг устгаад `game_event`-ийг `seq`-ээр дахин нугална. **Дараалал нь `seq`-ээр, `at_ms`-ээр хэзээ ч биш:** ханын цаг хоцорч, ухарч, цагийн хэлтэс солиж чадна.

### 4.2 Дүрийг дискэнд бичихгүйгээр сэргээх нь

10 §4 хэлдэг: дүрийн хүснэгт `lib/data/`-д хүрэхгүй. 13-ийн C2 хэлдэг: сэргэхэд дүр өөрчлөгдөхгүй. Хоёуланг нэг замаар хангана — **`game` нь `seed0_hex`, `entropy_hex`, `deal_id` гурвыг хадгална, `AppStart` нь тараалтыг seed-ээс ДАХИН ГАРГАНА.** Томьёо нь **GDD-10 §2**: `seed = sha256(utf8("HOTUNTLAA/v1") ‖ hex(dealId) ‖ seed0 ‖ userEntropy)`. (05 §6-ын нээлттэй асуулт 6 үүнийг «хамгийн хямд» гэж аль хэдийн нэрлэсэн.) Дүр нь RAM-д, `GameSession`-ий `final Map` хэвээр. `game_seat.role` нь **зөвхөн `closeGame()`-д**, `GAME_ENDED`-ийн дараа бичигдэнэ — дэвтрийн хуудас ба «Хөзрөө нээе»-д тэр үед л хэрэгтэй.

10 §4-ийн шалгуурыг нарийвчилъя: `rg 'role' lib/data/` → **зөвхөн `closeGame()`-д хит**. Шударгаар хэлье: `seed0` ба энтропи хоёулаа дискэн дээр байгаа тул тараалтыг дахин гаргаж болно. Энэ бол root эрхтэй халдагчийн эсрэг хамгаалалт биш, **UI-ийн эсрэг** хамгаалалт — ангийн жинхэнэ эрсдэл бол дүрийн жагсаалт харуулдаг дэлгэц, файлын систем биш.

## 7. Хураах (pruning)

**Бүртгэл сүүлийн 20 тоглолтод бүтнээр үлдэнэ.** Тоо 20 бол зохиогдсон биш: 09 §1 аль хэдийн `pin_mark`/`whisper_tap`-ийг яг тэр цонхоор цэвэрлэдэг. Хоёр тоо байхаас нэг тоо байх нь дээр.

| Дүрэм | Тоо |
|---|---|
| `game_event` бүтнээр | **сүүлийн 20 тоглолт** (≈460 КБ) |
| 21-ээс хойш | `game_event` устгагдана, `log_pruned=1`. Толгой мөр ба `game_seat` **үүрд** |
| Дэвтрийн мөрүүд | **Үүрд.** 200 тоглолт ≈ 300 КБ (09 §1) |
| Сангийн хатуу тааз | **8 МБ**; давбал 20 → **10** болж яаралтай хурааж `incremental_vacuum(64)` |
| Хэзээ ч хураагдахгүй | `klass`, `seat`, `title_award`, `class_config`, `app_setting` |
| Хураалт хэзээ | Хүйтэн эхлэхэд **ба** `GAME_ENDED`-ийн дараа. **Тоглолтын дунд хэзээ ч биш.** |
| `state='in_progress'` | **Хэзээ ч хүрэхгүй** — тест шалгана |

```sql
DELETE FROM game_event WHERE game_id IN (
  SELECT id FROM game WHERE state <> 'in_progress' AND log_pruned = 0
  ORDER BY started_at DESC LIMIT -1 OFFSET 20);
-- дараа: UPDATE game SET log_pruned=1 ...; PRAGMA incremental_vacuum(64);
```

Хумигдсан хуудсанд 📌-ийн мөчүүд алга болно, гэхдээ **толгой мөр бүрэн хэвээр**: 09 §2-ийн `GamePageScreen`-ий бүх мөр үүрд уншигдана, зөвхөн «Өнөөдрийн тэмдэглэл» хоосорч, нэг мөр гарна — **«Тэмдэглэл хураагдсан.»**

## 8. Схемын хувилбар ба миграц

**`drift`-ийн `schemaVersion` бол цорын ганц үнэн** (drift түүнийг `PRAGMA user_version`-д бичдэг). 09 §5-ийн дүрэм хүчинтэй: **өгөгдөл устгадаг миграц хэзээ ч бичигдэхгүй; багана нэмнэ, хаяхгүй.** GDD-12 дөрөв нэмнэ:

| Дүрэм | Юу гэсэн үг |
|---|---|
| **Зөвхөн урагш** | `user_version > schemaVersion` (хуучин APK буулгасан) бол өгөгдөлд **хүрэхгүй**: «Апп хуучирсан. Шинэчилнэ үү.» → зөвхөн-унших. Хагас миграцлагдсан файл бол алдагдсан дэвтэр. |
| Нэг транзакц + `angi.sqlite.bak` | Амжилттай бол `.bak` шууд устана; амжилтгүй бол сэргээгээд зөвхөн-унших. |
| `payload_json` **миграцлагдахгүй** | Шинэ утга = шинэ `type`. Энэ бол «зөвхөн нэмэгддэг»-ийн жинхэнэ гэрээ. |
| Дэлгэц | 2 сек-ээс урт бол «Дэвтрээ шинэчилж байна…», өөр текст байхгүй. |

09 §5-ийн `migration_test.dart` нь `game_event` бүхий v1 файлыг assets-аас ачаалж, миграцлаад **мөрийн тоо тэнцүү** байхыг шалгах болж өргөжнө.

## 9. Экспорт, импорт, устгах

09 §1 гарцыг аль хэдийн тодорхойлсон: Тохиргоо → **«Дэвтрээ хуулах»** → SAF-аар `angi-2027-03-14.json`; импорт нь `schemaVersion` таарахгүй бол **татгалзана, дуугүй өнгөрөхгүй**. GDD-12 гурав нэмнэ:

| Шийдвэр | Дэлгэрэнгүй |
|---|---|
| **`game_event` экспортод ОРОХГҮЙ** | Түүхий товшилт (хэн хэнийг шивнэсэн) хоёр жилийн дараа ангид зэвсгээс өөр үнэ цэнгүй — 09 §5-ийн цонхны логик яг ижил. Файл нь **зөвхөн дэвтэр**: `klass`, `seat`, `game`, `game_seat`, `title_award`, `class_config`. |
| **«Хөгжүүлэгчийн экспорт»** | Хувилбарын дугаарыг 7 удаа дарж гарна; `angi-full-<огноо>.json` нь бүртгэлийг хамарна. Зөвхөн M2.5-ийн хэмжилтэд. |

| **«Бүх өгөгдлийг устгах»** | Хоёр товшилт, хоёр дахь товч **3 секунд бүдэг**. Бичвэр: **«Ангийн дэвтэр, суудлын жагсаалт, бүх тоглолт, бүх цол — бүгд устана. Буцаах боломжгүй.»** Хэрэгжилт: сангаа хаах → `angi.sqlite`, `-wal`, `-shm` **гурвууланг устгах** → хоосон сан үүсгэх. **`DELETE FROM` хэзээ ч биш** — тэр нь мөрүүдийг freelist хуудсанд байтаараа үлдээдэг. |

09 §1-ийн **«Миний нэрийг хас»** өөрчлөгдөхгүй: `seat.label` хоосорно, цол үлдэнэ. **Данс устгах товч байхгүй, учир нь данс байхгүй** (Apple 5.1.1(v) нь «supports account creation» дээр хамаарна).

## 10. Нэг ч байт гарахгүй

`AndroidManifest.xml`-д **`INTERNET` зөвшөөрөл огт байхгүй**, `allowBackup="false"`, `dataExtractionRules` бүгд deny (09 §1). Авто-нөөцлөлт `angi.sqlite`-г Google Drive руу зөөх байсан — тэр бидний цуглуулалт биш, гэхдээ «нэг ч байт гарахгүй»-г **үгчилсэн үнэн** байлгах нь 00 §3-ын 4-р багана. Өртөг: утас сольсон хүүхэд дэвтрээ алдана; хариулт нь §9.

**CI-ийн 3 шалгуур, build унагана:** (1) нэгтгэсэн манифестад `android.permission.INTERNET`; (2) `pubspec.lock`-д `http`, `dio`, `web_socket_channel`, `firebase_*`, `posthog*`, `flutter_tts`; (3) Dart кодод `HttpClient`, `Socket.connect`, `NetworkInterface`.

**Play Data safety (v1):** цуглуулдаг/хуваалцдаг уу — **Үгүй**. Гүйцэтгэл/эвдрэлийн бүртгэл — **Үгүй** (13 §8-ийн `crash.log` нь төхөөрөмж дээр үлддэг, хэрэглэгч **өөрөө** share sheet-ээр илгээнэ; автоматаар юу ч явахгүй). Төхөөрөмжийн танигч, `AD_ID` — **Үгүй, ямар ч build дээр**. Устгах хүсэлтийн зам — шаардлагагүй, гэхдээ апп дотор товч байна. Эрхийг Google өөрөө өгсөн: *«User data … only processed locally on the user's device and not sent off device does not need to be disclosed»* (17 §0.5).

## Нээлттэй асуулт

1. **`synchronous=FULL` хэр үнэтэй вэ?** Redmi 9A ба Huawei дээр M1-д хэмж. **< 25 мс** бол шийдвэр хүчинтэй. 25–60 мс бол `NORMAL` + үе шатны заагт `wal_checkpoint(TRUNCATE)` — алдагдал нэг үйлдлээс нэг үе шат болж өснө. **> 60 мс** бол шөнийн 6 секундын хэмнэл эвдэрнэ: `commit`-ыг дараагийн суудал рүү шилжих анимацтай **зэрэгцүүлж** гүйцэтгэ.
2. **20 тоглолт хэтэрхий бага уу?** M2.5-ийн таван суултын дараа асуу: хэн нэг нь **гурван** долоо хоногийн өмнөх 📌 тэмдэглэлээ хайв уу? Хайвал таазыг **50** болго (+230 КБ, кодын өөрчлөлт нэг тоо). Хэн ч хайхгүй бол 20 хэвээр.
3. **Сэргээлтийн дэлгэц хэдэн удаа гарав?** Таван суултад **нэгээс** олон бол унаж байгаа шалтгаан нь сэргээлтийн өнгөлгөөнөөс чухал: `crash.log`-ыг унш.
4. **`game_event`-ийг экспортоос хассан нь зөв үү?** Анги «тэр өдрийн бүх товшилтыг харъя» гэж хүсвэл 09 §5-ийн цонхны логик няцаагдана, бөгөөд бүртгэлийг **суудлын дугааргүйгээр** экспортлох гурав дахь хувилбар гарна (+0.5 хоног).
5. **§4.2-ыг тусламжийн дэлгэцэд тайлбарлах уу?** «Дүр утсан дээр хадгалагддаггүй» гэж бичих нь хагас үнэн — `seed0`+`shake` байгаа. **Шийдвэр: тэр өгүүлбэрийг бичихгүй.** Асуувал үнэнээ хэл: «Утас дүрийг санадаггүй, харин дахин бодож чадна.»
6. **`BEST_MOVE_SPOKEN`-д зөвхөн тоо бичих нь хүрэлцэх үү?** Хэн нэг нь «би юу гэж хэлсэн бэ?» гэж асуувал v2-т дугааруудыг бичиж, **оноолохгүйгээр** дэвтэрт харуулна. Хэн ч асуухгүй бол одоогийн шийдвэр зөв.
7. **8 МБ-ын тааз цохигдох уу?** Тооцоогоор үгүй (200 тоглолт ≈ 760 КБ). Цохигдвол бүртгэлд байх ёсгүй зүйл бичигдэж байна — таазыг өсгөхөөс өмнө `SELECT type, COUNT(*) FROM game_event GROUP BY type`-ыг унш.
