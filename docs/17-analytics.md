## 1. Бүтцийн асуудал: офлайн тоглоом гэр лүүгээ утасдаж чадахгүй

### 1.1 Хязгаарлалт яг юу вэ

Бүлэг 06-ийн Tier 0 нь *«v1.0-ийн manifest дотор `INTERNET` зөвшөөрөл байхгүй»* гэж амласан.
Android дээр `android.permission.INTERNET`-ыг орхивол socket дуудлага бүр алдаа шиднэ; ямар ч
аналитик SDK ажиллаж чадахгүй, бас чимээгүйхэн холбогдож ч чадахгүй. Энэ бол таагүй байдал биш —
Google Play-ийн тодорхойлолтоор **цуглуулах гэдэг нь «хэрэглэгчийн төхөөрөмжөөс гадагш өгөгдөл
дамжуулах»**, үүнд SDK, сангуудаар дамжуулсан нь ч орно. Мөн **«Таны аппын хандсан, зөвхөн
хэрэглэгчийн төхөөрөмж дээр локалаар боловсруулагдаж, төхөөрөмжөөс гадагш илгээгддэггүй
хэрэглэгчийн өгөгдлийг Data safety хэсэгт зарлах шаардлагагүй»**.

Тиймээс `INTERNET`-гүй build нь **«Ямар ч өгөгдөл цуглуулдаггүй»** гэж зарлана. Сошиал сүлжээний
хоригийн үед монгол сурагчдад зориулсан бүтээгдэхүүний хувьд энэ бол авч болох хамгийн хүчтэй
байр суурь.

### 1.2 Гурван сонголт, бүрэн өртөгтэйгөө

| | **А. Сохроор гаргах (v1.0)** | **Б. Локалд дараалуулж, зөвшөөрлөөр илгээх** | **В. Байнга асаалттай аналитик** |
|---|---|---|---|
| Manifest | `INTERNET` **байхгүй** | v1.1-ээс `INTERNET` нэмэгдэнэ | v1.0-аас `INTERNET` байна |
| Data safety маягт | **«Ямар ч өгөгдөл цуглуулдаггүй»** | «Аппын харилцан үйлдэл — **Сонголтоор**, цуглуулдаг, хуваалцдаггүй» | «Аппын харилцан үйлдэл — Заавал» |
| Нууцлалын бодлого | Нэг догол мөр: «энэ горимд мэдээлэл цуглуулдаггүй» | Зорилго, хүлээн авагч, хадгалах хугацаа, **хил дамнасан шилжүүлгийн зөвшөөрөл** (Бүлэг 14 §3.3) нэмэх ёстой | Мөн адил, дээр нь COPPA-гийн хатуу байр суурь |

| Play Families | Хялбархан нийцнэ | `AD_ID` **шаардаж болохгүй** (API 33+); нас нь тодорхойгүй хэрэглэгчээс AAID дамжуулж болохгүй | Насны төвийг сахисан дэлгэц + өөрөө гэрчилсэн SDK шаардана |
| Балансын өгөгдөл | Зөвхөн ангид хийсэн ажиглалт | Хэрэглэгчийн **~10–30%** зөвшөөрнө *(таамаг — хэмж)* | ~100% |
| Хөгжүүлэлтийн зардал | 0 | **~3 өдөр** (бүртгэл + илгээлт + зөвшөөрлийн дэлгэц) | ~2 өдөр |

> харьцааг бод. §6-д гарсан бүх түүврийн тоог тэр харьцаанд хуваавал жинхэнэ *хуанлийн*
> хугацаа гарна.

**Шийдвэр: v1.0-д А, v1.1-ээс Б.** В сонголтыг шууд татгалзсан — тэр нь хуулийн хувьд ер бусын
энгийн байсан бүтээгдэхүүнийг, ашиглалтад орохоосоо өмнө Бүлэг 14 §6-ийн Монголын нутагшуулалтын
асуултуудад хариулах үүрэгтэй бүтээгдэхүүн болгож хувиргана.

### 1.3 Локал бүртгэл (үүнийг v1.0-д, сүлжээний кодгүйгээр бич)

Хамгийн том алдаа нь v1.0-ийг *огт хэмжилтгүй* гаргачихаад, дараа нь товч нэмэгдэхэд түүх нь тэг
байх явдал. Оронд нь эхний build-аас эхлээд үйл явдлуудаа зөвхөн нэмэгддэг (append-only) локал
хүснэгт рүү бич.

Доорх бол тэр бүртгэлийн SQL схем. `uploaded_at` нь зөвшөөрөлтэй илгээлт амжилттай болтол `NULL`
байна — өөрөөр хэлбэл «энэ мөрийг хэн ч хараагүй» гэсэн үг.

```sql
CREATE TABLE telemetry_queue (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  event_name  TEXT    NOT NULL,          -- 40 chars max, snake_case
  ts_local    INTEGER NOT NULL,          -- epoch ms, device clock
  ts_offset   INTEGER NOT NULL,          -- minutes from UTC; Mongolia = +480
  session_id  TEXT    NOT NULL,          -- uuid v4, rotates on cold start
  install_id  TEXT    NOT NULL,          -- uuid v4, generated on first run, NOT AAID/IDFA
  props_json  TEXT    NOT NULL,          -- typed properties, see §2
  schema_ver  INTEGER NOT NULL DEFAULT 1,
  uploaded_at INTEGER                    -- NULL until a consented upload succeeds
);
CREATE INDEX idx_pending ON telemetry_queue(uploaded_at) WHERE uploaded_at IS NULL;
```

Энэ бүртгэлийг Play-ийн «төхөөрөмжөөс гадагш илгээгддэггүй» гэсэн чөлөөлөлтийн дотор байлгаж,
**бас** хожим шинэчлэх боломжтой байлгах дүрмүүд:

- **Бүртгэлийг 5,000 мөр / 90 хоног** — аль нь эхэлж дүүрэхээр тэрээр таазал; хамгийн хуучныг нь
  хая. Өдөр бүр тоглодог анги нэг тоглоомд ойролцоогоор **40–80 мөр** үүсгэнэ.
- **`install_id` бол локалаар үүсгэсэн UUID**, хэзээ ч AAID/IDFA биш. Бүлэг 14 §3.5 нь 16-аас доош
  насныханд AAID хэрэглэхийг хориглосон, Play Families нь *«Зөвхөн хүүхдэд чиглэсэн аппууд Android
  API 33 ба түүнээс дээш түвшин рүү чиглэж байхдаа AD_ID зөвшөөрөл шаардах ёсгүй»* гэсэн.
  `com.google.android.gms.permission.AD_ID` зөвшөөрлийг **огт бүү нэм**.
- **Чөлөөт бичвэр хэзээ ч байхгүй.** A1 дэлгэц дээр оруулсан тоглогчийн нэрс бол насанд хүрээгүй
  хүний хувийн мэдээлэл. Тэднийг бичих мөчид нь тоглоом доторх дугаар (`p1…p20`) болгон хувирга;
  бүртгэлд нэр хэзээ ч байж болохгүй.
- **Илгээхийн өмнө хэрэглэгч ачааллыг урьдчилж харж чадна** («Юу илгээх вэ?» → гүйлгэх боломжтой
  JSON харагдац). Энэ бол Бүлэг 14 §3.3-д гарсан Монголын хуулийн зөвшөөрлийн жагсаалтад (зорилго,
  хянагч, өгөгдлийн жагсаалт, хугацаа, хүлээн авагчид, татгалзах арга) хамгийн хямдаар хариулах арга.
- **Татгалзвал бүртгэлийг устгана**, мөн илгээх төгсгөл цэг нь `install_id`-аар устгах дуудлагыг
  хүлээж авна.

## 2. Үйл явдлын схем (event schema)

### 2.1 Нэршлийн конвенц

`object_action`, `snake_case`. Болсон зүйлийг өнгөрсөн цагаар, төлөвийг одоо цагаар. Хязгаарлалтууд
нь схемийг дахин бичихгүйгээр GA4 руу зөөх боломжтой байхаар сонгосон:

| Дүрэм | Хязгаар | Яагаад |
|---|---|---|
| Үйл явдлын нэр | ≤ **40** тэмдэгт, `[a-z0-9_]` | GA4-ийн үйл явдлын нэрийн хязгаар 40 тэмдэгт |
| Шинж чанарын нэр | ≤ **40** тэмдэгт | GA4-ийн үйл явдлын параметрийн нэрийн хязгаар |
| Шинж чанарын утга (мөр) | ≤ **100** тэмдэгт | GA4-ийн параметрийн утгын хязгаар |
| Нэг үйл явдал дахь шинж чанар | ≤ **20** захиалгат | GA4 нь автомат цуглуулсныг **оруулаад** 25-ыг зөвшөөрдөг |
| Ялгаатай үйл явдлын нэр | ≤ **60** (хатуу төсөв) | GA4-ийн app stream нь **500** ялгаатай нэрээр тааздаг |
| Хэрэглэгчийн шинжийн нэр / утга | ≤ **24 / 36** тэмдэгт | GA4-ийн user-property хязгаар |
| Аль ч шинж чанарт PII байхгүй | — | Бүлэг 14 §3.5 |

Хувьсагчийг үйл явдлын нэр дотор хэзээ ч бүү тавь (`role_revealed_doctor` бол буруу;
`role_revealed` дээр `role="doctor"` гэж өгөх нь зөв) — 500 нэрийн тааз яг ингэж шатдаг.

> **Юу гэсэн үг вэ? — PII**
> PII (personally identifiable information) бол тухайн хүнийг таньж болохоор мэдээлэл: нэр,
> утасны дугаар, и-мэйл, зураг. Манай бүртгэлд зөвхөн `p1…p20` гэсэн дугаар л байна.

### 2.2 Үйл явдал бүрт дагалдах шинж чанарууд

| Шинж чанар | Төрөл | Жишээ | Тэмдэглэл |
|---|---|---|---|
| `install_id` | string(36) | uuid | хэрэглэгчийн шинж, үйл явдлын шинж биш |
| `session_id` | string(36) | uuid | хүйтэн эхлэл / 30 мин арын дэвсгэрийн дараа солигдоно |
| `app_version` | string | `1.2.0` | |
| `schema_ver` | int | `1` | эвдрэлтэй өөрчлөлт бүрт нэмэгдүүлнэ |
| `locale` | string | `mn-MN` | Бүлэг 13-ийн нутагшуулалтад `mn` ба `ru`/`en`-ийн ялгаа хэрэгтэй |
| `device_tier` | enum | `low`\|`mid`\|`high` | RAM + API түвшнээс гаргана; Бүлэг 08 сул төхөөрөмжид анхаардаг |
| `mode` | enum | `offline_pass`\|`offline_room`\|`online` | Бүлэг 06-ийн түвшин |
| `is_first_session` | bool | | |
