# Бүлэг 07 — Бодит цагийн backend архитектур

> **Гол дүгнэлт**
> - **Мафи бол ээлжит тоглоом. Нэг үе шат 30–180 секунд үргэлжилдэг. Тэгэхээр саатал (latency) чамд ЯМАР Ч хамаагүй.** Монголоос хамгийн ойрын cloud бүс хүртэл **106–116 мс**. 45 секундын санал өгөх үе шатанд 110 мс гэдэг юу ч биш. Backend-ээ хурдаар нь БИШ, **ops ачаалал, зардал, нуугдмал мэдээллийн аюулгүй байдлаар** нь сонго.
> - **Офлайн горим (Горим A) backend огт шаардахгүй.** Эхлээд 100% локал апп гарга: серверийн зардал тэг, Wi-Fi байхгүй ангид ажиллана, ангийнхан чинь яг одоо тэгж тоглодог. Горим B (онлайн) зөвхөн хожим хэрэгтэй.
> - **Сонголт: Colyseus 0.16 (нээлттэй эх) → Fly.io `nrt` (Токио) дээр нэг Machine.** ~$6–35/сар. Дараагийн шат нь Cloudflare Durable Objects. Мафийн өрөө бол **яг нэг Durable Object** — нэг урсгалтай, дан төлөвтэй, өөрийн санах ой ба сэрүүлэгтэй жүжигчин.
> - **Хамгийн чухал дүрэм: сервер тоглогчийн харах эрхгүй ганц ч байт илгээхгүй.** Шифрлээд биш, UI дотор нуугаад биш, «клиент шүүнэ» гээд биш — **байхгүй** байх ёстой. Энэ бол бүх нуугдмал дүртэй тоглоомын цорын ганц жинхэнэ хамгаалалт.
> - **10,000 MAU дээр чиний бодит цагийн тооцоо сард $12–25 байх ёстой.** Ангийн мафийн тоглоомд сард $600-ын backend зарж байгаа хэнд ч бүү итгэ.
> - **Дүрмийн код (`/packages/rules`) цэвэр, платформгүй байна.** Тэгвэл Горим A (офлайн хөтлөгч) ба Горим B (онлайн) **нэг дүрмийн номыг** хуваалцана: нэг монгол дүрмийн текст, нэг багц тест, хоёр тээвэр.

## 0. Хамгийн чухал ганц олдвор

**Мафи бол 30–180 секундын үе шаттай ээлжит тоглоом. Хоёр талын аялалын саатал (round-trip latency) энэ тоглоомд огт хамаагүй.**

Монголоос хамгийн ойрын cluster хүртэлх хэмжигдсэн саатал ойролцоогоор **106–116 мс**:

| Хэмжилт | Утга | Огноо / эх сурвалж |
|---|---|---|
| Монголын оффисоос → Oracle-ийн Tokyo ба Seoul бүс | 106–110 мс дундаж | LinkedIn-ий saatal тест (Bilegt Bat-Ochir), нийтийн интернэт |
| Монголын сургуулиудаас **Seoul**-ын speedtest сервер хүртэлх улсын дундаж саатал | **116 мс** | Giga/UNICEF, хэмжилтийн цонх 2025.08.16 – 2025.12.14 |
| Мөн сургуулиудаас **дотоодын** (Монголын) сервер хүртэл, 2025.10.15-ны сервер шилжүүлснээс хойш | **8 мс** | мөн тэр эх сурвалж |
| Seoul хүртэлх hop / зай | 7 IP hop, ~3,200 км | мөн тэр эх сурвалж |
| Монголын мобайл татах дундаж хурд | 20.61 Mbps | DataReportal Digital 2025 Mongolia, 2025.03.03 |
| Суурин холболтын татах дундаж хурд | 74.07 Mbps | мөн тэр |
| Интернэт хэрэглэгч / нэвтрэлт | 2.90 сая / 3.50 сая хүн амын 83.0% | мөн тэр |
| Мобайл холболт | 4.92 сая (хүн амын 141%) | мөн тэр |
| **Гадаадад** байрлах видеог урсгаж чаддаг сургууль | **42%** (дотоодынхыг 79%) | Giga, 2025.12 |

Монгол бол **далайд гарцгүй, шумбагч кабелийн буулт огт байхгүй** улс. Бүх олон улсын урсгал эхлээд Орос эсвэл Хятадаар газрын фибрээр гарч, дараа нь Хонг Конг, Сингапур эсвэл Франкфуртын транзитад хүрдэг. Giga үүнийг шууд хэлсэн: "Mongolia is landlocked, with no direct submarine cable connection", мөн гадаад контентын хүсэлт "must cross a border on terrestrial fibre — through Russia or China — before reaching transit providers in Hong Kong, Singapore, or Frankfurt" (giga.global, 2026-09-15-нд баталгаажуулав).

**Юу гэсэн үг вэ?** Чиний пакет Токио хүртэл яваад ирэхэд 0.11 секунд болно. Хүн нэг үг хэлж амжихгүй хугацаа. Гэхдээ тэр урсгал **хилээр дамждаг** учраас заримдаа бүхэлдээ тасардаг. Тэгэхээр чи хурдны төлөө биш, **тасралтыг тэсвэрлэхийн төлөө** зохион бүтээх ёстой.

> **Баталгаажуулалт (2026-09-15):** Өмнөх ноорог энэ замыг «ERMC Europe–Russia–Mongolia–China систем, Сүхбаатар–Дархан–Улаанбаатар–Чойр–Замын-Үүдийн төмөр замын дагуух ~1,000 км давхар чиглүүлэгдсэн фибр» гэж тайлбарласан байсан. **Дурдсан эх сурвалжуудын аль нь ч үүнийг дэмжихгүй.** Giga-ийн нийтлэл ERMC-ийг ч, төмөр замыг ч, 1,000 км гэсэн тоог ч огт дурдаагүй (https://giga.global/two-internets-one-classroom-why-mongolias-130-mbps-tells-only-half-the-story/, 2026-09-15-нд уншив); https://www.submarinenetworks.com/en/systems/eurasia-terrestrial/ermc ямар ч агуулга буцаасангүй; https://www.gemnet.mn/international-transit-channel-and-rental-service/ зөвхөн Gemnet "provides international transit services between Asia and Europe through the Mongolian territory" гэж Хятад, Оросын операторуудаар дамжуулдаг гэсэн — зам, урт, давхар чиглүүлэлтийн ямар ч дэлгэрэнгүй байхгүй. ERMC-ийн нарийн мэдээллийг оператор эсвэл зохицуулагчийн баримтаар батлах хүртэл **[баталгаажаагүй]** гэж үз.

> **Баталгаажуулалт (2026-09-15):** Өмнөх ноорог «Монголд 2 идэвхтэй IXP, нийт 15 гишүүнтэй (ISOC Pulse, 2026.08), бөгөөд **аль нь ч 300,000-аас дээш хүн амтай хотод байхгүй**» гэж бичсэн байв. Сүүлийн хэсэг нь **худал**. PeeringDB (https://www.peeringdb.com/api/ix?country=MN, 2026-09-15-нд уншив) Монголд бүртгэлтэй **гурван** IXP жагсаасан — MIX MNDC, MISPA-IXP, IXP-MN — бөгөөд **бүгд Улаанбаатарт** байна. Улаанбаатар ~1.79 сая хүнтэй, улсын хүн амын бараг тэн хагасыг эзэлдэг (https://en.wikipedia.org/wiki/Ulaanbaatar, 2026-09-15-нд уншив). «2 идэвхтэй IXP / 15 гишүүн» гэсэн тоог дахин шалгах боломжгүй байсан: ISOC Pulse-ийн IXP tracker (https://pulse.internetsociety.org/en/ixp-tracker/country/MN/) автомат хүсэлтэд HTTP 403 буцаадаг — **[баталгаажаагүй]**. Нэг IXP-д ногдох гишүүний тоогоор бол peering тун нимгэн хэвээр, гэхдээ анх хэлсэн шалтгаанаар нь биш.

**Архитектурт үзүүлэх үр дагавар:**

1. Backend-ээ **tick-rate буюу саатлаар БҮҮ сонго**. 45 секундын санал өгөх үе шатанд 110 мс хангалттай сайн. *Ops ачаалал, зардал, нуугдмал мэдээллийн аюулгүй байдлаар* сонго.
2. Саатал биш, **пакет алдагдал ба дахин холболтод** оновчил. Сургуулиудын 58% нь гадаад видео урсгаж чаддаггүй — энэ бол *дамжуулах чадвар/тогтвортой байдлын* асуудал. Чиний протокол 30–90 секундын тасалдлыг тоглоомыг дуусгалгүй тэсвэрлэх ёстой.
3. Сонгох боломжтой бол серверээ Сингапурт биш, **Токио (ap-northeast-1) эсвэл Сөүлд (ap-northeast-2)** тавь — Giga-ийн хэмжилтийн зам Сөүлээр дамждаг. Сингапур Зүүн хойд Ази дээр ~30–60 мс нэмнэ **[баталгаажаагүй; Улаанбаатарын ISP (Mobicom, Univision, Gemnet гэх мэт)-ээс `mtr` ажиллуулж шалга]**.
4. **Ачааллаа жижиг байлга.** 20 Mbps дундаж мобайл хурд, бодит амьдралын түгжрэлтэй үед үе шат бүрт 200 KB төлөвийн блоб × 10 тоглогч гэдэг бол дэмий үрэлгэн. Бүтэн төлөв биш, секунд тутмын тоолуурын tick биш — **дельта ба эцсийн хугацаа (deadline)** илгээ.

**Бүтээгдэхүүний шийдвэрлэх цэг: Горим A (офлайн / нүүр тулсан, утас дамжуулах) бодит цагийн backend ОГТ шаардахгүй.** Горим A-г 100% локал апп болгож эхлээд гарга. Дэд бүтцийн зардал тэг, Wi-Fi байхгүй ангид ажиллана, чиний хэрэглэгчид яг тэр горимоор нь одоо тоглож байна. Доорх бүхнийг зөвхөн Горим B (танихгүй хүмүүстэй онлайн) шаардана.

## 3. Зөвлөмж болгож буй архитектур

### 3.1 Өрөөний амьдралын мөчлөгийн төлөвт машин

`phase`, `phaseEndsAt` (абсолют epoch мс), `round`, `seq` дөрвийг хадгал. Секунд тутмын tick **хэзээ ч** бүү илгээ; эцсийн хугацааг нэг удаа илгээгээд клиент өөрөө локалаар тоолог, ирсэн мессеж болгон дээр дахин тааруулна.

| # | Үе шат | Үргэлжлэх хугацаа (анхдагч) | Хэн команд илгээж болох | Сервер юу цацах |
|---|---|---|---|---|
| 0 | `LOBBY` | host эхлүүлэх хүртэл / 10 мин зогсонги | бүгд: `SET_READY`, `CHANGE_NAME`, `LEAVE`; host: `START`, `CONFIG` | тоглогчдын жагсаалт, тохиргоо, тоолуур |
| 1 | `ROLE_ASSIGN` | **8 сек** | хэн ч үгүй | socket тутамд **хувийн** `YOUR_ROLE`; нийтэд зөвхөн `ROLE_COUNTS` |
| 2 | `NIGHT` | **35 сек** (20–60 хооронд тохируулж болно) | зөвхөн энэ шөнө үйлдэл хийх дүртэй амьд тоглогчид | нийтэд: «Хот унтлаа» дохио + эцсийн хугацаа. хувийн: үйлдэгч тус бүрийн зөвшөөрөгдсөн бай нэрсийн жагсаалт |
| 3 | `NIGHT_RESOLVE` | 0 сек (синхрон) | хэн ч үгүй | нийтэд `NIGHT_REPORT` (зөвхөн хохирогчид, үйлдэгчийг хэзээ ч биш); хувийн үр дүн (Мөрдөгчийн шалгалтын хариу) |
| 4 | `DAY_DISCUSS` | **120 сек** (эсвэл амьд тоглогч тутамд 30 сек) | амьд: `CHAT`, `SKIP_VOTE` | чат тараалт, эцсийн хугацаа |
| 5 | `NOMINATE` | **45 сек** | амьд: `NOMINATE(targetId)` (тус бүр 1 удаа) | нэр дэвшүүлэлтийн явцын тоо |
| 6 | `VOTE` | **30 сек** | амьд: `VOTE(nomineeId эсвэл ABSTAIN)` | **хаагдах хүртэл тоо нуугдана** (§3.4-г үз) |
| 7 | `DEFENSE` | **45 сек** | зөвхөн буруутгагдсан хүн: `CHAT` | хэн буруутгагдсаныг |
| 8 | `FINAL_VOTE` | **25 сек** | буруутгагдсанаас бусад амьд: `GUILTY`/`INNOCENT` | зөвхөн хаагдах үед тоо |
| 9 | `EXECUTE` | **6 сек** | хэн ч үгүй | үр дүн + **хотоос хөөгдсөн тоглогчийн дүрийг зөвхөн `config.revealRoleOnDeath` асаалттай үед нээнэ** |
| 10 | `WIN_CHECK` | 0 сек | хэн ч үгүй | → `NIGHT` (round+1) эсвэл `GAME_OVER` |
| 11 | `GAME_OVER` | **30 сек** | `REMATCH` | бүх дүрийг нээх + үйл явдлын лог |

Зөвшөөрөгдсөн шилжилтүүд (бусад бүхнийг татгалзана):

```
LOBBY → ROLE_ASSIGN → NIGHT → NIGHT_RESOLVE → WIN_CHECK
WIN_CHECK → DAY_DISCUSS | GAME_OVER
DAY_DISCUSS → NOMINATE → VOTE
VOTE → DEFENSE (if quorum) | DAY_DISCUSS (if none) 
DEFENSE → FINAL_VOTE → EXECUTE → WIN_CHECK
WIN_CHECK → NIGHT | GAME_OVER
GAME_OVER → LOBBY (rematch)
any → ABORTED (all humans gone / host cancel)
```

### 3.2 Үйл явдалд суурилсан тоглоомын лог (event-sourced)

Өрөөний эрх мэдэлтэй санах ой бол **зөвхөн нэмэгддэг (append-only) үйл явдлын массив**. Бусад бүхэн бол түүний проекц.

```ts
type GameEvent =
  | { t:'GAME_STARTED';   seed:string; config:RoomConfig }
  | { t:'ROLES_ASSIGNED'; assignment: Record<PlayerId, RoleId> }   // NEVER projected to clients
  | { t:'PHASE_ENTERED';  phase:Phase; round:number; endsAt:number }
  | { t:'NIGHT_ACTION';   actor:PlayerId; role:RoleId; target:PlayerId|null }
  | { t:'NIGHT_RESOLVED'; deaths:PlayerId[]; saves:PlayerId[]; checks:Array<{by:PlayerId;on:PlayerId;result:'MAFIA'|'CITIZEN'}> }
  | { t:'CHAT';           from:PlayerId; text:string; channel:'DAY'|'MAFIA'|'DEAD' }
  | { t:'NOMINATED';      by:PlayerId; target:PlayerId }
  | { t:'VOTED';          by:PlayerId; target:PlayerId|'ABSTAIN' }
  | { t:'EXECUTED';       target:PlayerId|null }
  | { t:'PLAYER_LEFT' | 'PLAYER_RECONNECTED'; who:PlayerId }
  | { t:'GAME_ENDED';     winner:'MAFIA'|'CITY'|'DRAW' }
```

```
state_public(n)        = fold(events[0..n], publicReducer)
state_private(n, pid)  = fold(events[0..n], privateReducer(pid))
```

Үнэгүй дагалдах давуу талууд: детерминист replay («би яагаад үхэв?» гэдгийг харуулах, залилангийн гомдлыг шалгахад гайхалтай), дахин холболт нь өчүүхэн амархан болох (`resume(sinceSeq)`), мөн тестлэх боломж — чиний бүх дүрмийн багц сүлжээгүйгээр unit-тест хийж болох цэвэр функц болж хувирна.

**`seed`-ээ хадгалж, seed-тэй PRNG ашигла** (ж нь `xorshift128`/`sfc32`) — дүр хуваарилалт болон бусад бүх RNG-д. Тэгвэл replay яг таг давтагдана.

### 3.3 Шөнийн үйлдлийн шийдвэрлэх дараалал (детерминист, тэнцэхгүй)

Ирсэн дарааллаар нь БИШ, тогтсон эрэмбээр шийдвэрлэ:

| Эрэмбэ | Дүр | Үйлчлэл |
|---|---|---|
| 10 | Саатуулагч (нэмбэл) | байг `blocked` гэж тэмдэглэнэ — саатуулагдсан үйлдэгчийн үйлдэл хаягдана |
| 20 | Эмч (`emch`) | байг `protected` гэж тэмдэглэнэ; сонголтоор `cannotHealSelfTwiceInARow` |
| 30 | Мафи / Алуурчин (`aldarch`) | байг `attacked` гэж тэмдэглэнэ (нийтийн ганц ална; мафи санал зөрвөл эхний санал хожно, эсвэл seed-ээр санамсаргүй) |
| 40 | Мөрдөгч (`tsagdaa`) | `check`-ийн үр дүнг бичнэ — **шийдвэрлэхээс ӨМНӨХ** талыг үндэслэн тооцно |
| 50 | Шийдвэрлэлт | `died = attacked && !protected` |
| 60 | Ялалтын шалгалт | доороос үз |

Ялалтын нөхцөл, хохирогч гарах бүрд шалгана:

```
mafiaAlive == 0                      -> CITY wins
mafiaAlive >= (aliveTotal - mafiaAlive) -> MAFIA wins   // mafia >= citizens
aliveTotal == 0                      -> DRAW
```

### 3.4 Манангийн сериализаци (fog-of-war) — хэлэлцэхгүй дүрэм

> **Дүрэм: сервер тоглогчийн харах эрхгүй ганц ч байт илгээхгүй. Шифрлээд биш, хумигдсан UI дотор нуугаад биш, «клиент шүүнэ» гээд биш. БАЙХГҮЙ.**

Colyseus 0.16 дээрх бодит хэрэгжүүлэлт:

```ts
class Player extends Schema {
  @type("string") id!: string;
  @type("string") name!: string;
  @type("boolean") alive = true;
  // role tagged as a view-only field: only clients whose StateView contains
  // THIS Player instance (with tag 1) will ever receive these bytes
  @view(TAG_SELF) @type("string") role!: string;
  @view(TAG_MAFIA) @type("boolean") isMafia!: boolean;
}

onJoin(client, opts, auth) {
  client.view = new StateView();
  client.view.add(playerOf(client), TAG_SELF);         // sees only own role
}
onRolesAssigned() {
  for (const c of mafiaClients) for (const m of mafiaPlayers) c.view.add(m, TAG_MAFIA);
}
onDeath(p) { if (config.revealRoleOnDeath) everyone.view.add(p, TAG_SELF); }
```

Durable Objects дээр яг үүнийг гараараа хийнэ: `secret`-ийг DO storage дотор байлгаж, socket тутмын гарах frame-ийг `projectFor(playerId, state)`-ээр угсарна. Дүр бүрд нэг unit-тест нэмээд
`JSON.stringify(frameFor(citizenId)).includes(mafiaId) === false` гэдгийг батал.

**Саналыг нуух:** `VOTE` ба `FINAL_VOTE` үе шатанд зөвхөн `{votedCount: n, totalVoters: m}` цац. Хэн хэнд санал өгснийг `EXECUTE` үйл явдал дээр нийтэл. Үгүй бол пакет чагнагч санал өгөхөөс өмнө үр дүнг мэднэ.

**Чатын сувгууд:** `MAFIA` чат зөвхөн мафийн багц дахь socket-уудад тарна; `DEAD` чат зөвхөн хасагдсан тоглогчдод. `channel` талбартай ганц нийтийн цацалт хийж, «клиент хүндэтгэнэ биз» гэж бүү найд.

### 3.5 Restart-ыг давж гардаг таймерууд

Нүцгэн `setTimeout` бүү ашигла. Эцсийн хугацааг хадгал, ачаалахдаа дахин зэвсэглэ.

| Платформ | Механизм | Restart дээрх зан төлөв |
|---|---|---|
| Cloudflare DO | `state.storage.setAlarm(phaseEndsAt)` + `async alarm(alarmInfo)` | **Дор хаяж нэг удаа баталгаатай ажиллана**, 2 секундээс эхлэн экспоненциал ухралттайгаар автоматаар **6 хүртэл удаа** дахин оролдоно; `alarmInfo.retryCount` / `isRetry`-ээр handler-ээ idempotent болгож болно. Объект тутамд **ганц** alarm — хуваарийг хадгалж, handler дотроо дахин зэвсэглэ. |
| Colyseus | `this.clock.setTimeout(...)` **дээр нэмээд** шилжилт бүр дээр `{roomId, phase, phaseEndsAt}`-ыг Postgres/Redis-д хадгална; процесс ачаалахад sweeper нь `phaseEndsAt < now` болсон өрөөнүүдийг сэргээнэ | Сэргээлт чиний хариуцлага. |
| Node/Socket.IO | Redis-ийн эрэмбэлэгдсэн олонлог `ZADD deadlines phaseEndsAt roomId` + 1 секунд тутмын sweeper давталт | Сэргээлт чиний хариуцлага. |

Үе шат урагшлуулах handler-ээ `(roomId, round, phase)`-оор хамгаалж idempotent болго:

```ts
async advancePhase(expected: {round:number; phase:Phase}) {
  if (this.state.round !== expected.round || this.state.phase !== expected.phase) return; // already advanced
  ...
}
```

### 3.6 Дахин холболт ба үргэлжлүүлэх

Монголын мобайл сүлжээ тоглогчийг тойргийн дундуур унагаана. Үүнд нь зориулж зохио:

1. Нэгдэх үед **`resumeToken`** = HMAC(`roomId|playerId|gameId`, serverSecret) олго. Клиентийн аюулгүй хадгалалтад хий. Суудал руугаа буцах цорын ганц зам нь энэ.
2. Холболт тасрахад тоглогчийг **бүү хас**. `connected=false` гэж тэмдэглэ, суудлыг нь үлдээ, **90 секундын хүлээх цонх** эхлүүл (Colyseus-д `allowReconnection(client, 90)`; DO-д хадгалсан `disconnectedAt` + alarm).
3. `PLAYER_DISCONNECTED` цац — бусад нь сүнс биш, Wi-Fi дүрс харна.
4. Дахин холбогдоход клиент `{resumeToken, lastSeq}` илгээнэ. Сервер `events[lastSeq+1..]`-ийг *тухайн тоглогчийн проекцоор шүүж* дахин тоглуулна, зөрүү том бол дээр нь шинэ snapshot нэмнэ.
5. Хүлээх цонх дуусвал: **AFK бодлого** — тоглогч санал өгөхөөс автоматаар татгалзаж (алгасаж), шөнийн үйлдэл нь `null` болно (эсвэл санамсаргүй — тохируулж болно). Автоматаар **бүү ал**; тэр нь мафид үнэгүй ялалт өгнө. Мафийн гишүүн салбал тэр шөнийн алалт алгасана.
6. **Host** салбал host-ыг хамгийн удаан холбогдсон амьд тоглогч руу автоматаар шилжүүл.

### 3.7 Idempotent командууд

Клиент→сервер команд бүр `{cmdId: uuid, roomId, expectedPhase, expectedRound}` авч явна.

```ts
handle(cmd) {
  if (this.seenCmdIds.has(cmd.cmdId)) return this.ackCache.get(cmd.cmdId); // dedupe retries
  if (cmd.expectedPhase !== this.state.phase) return err('STALE_PHASE');   // reject late frames
  if (!this.isLegal(cmd, sender)) return err('ILLEGAL');                    // authority check
  const ack = this.apply(cmd);
  this.seenCmdIds.add(cmd.cmdId); this.ackCache.set(cmd.cmdId, ack);
  return ack;
}
```

`seenCmdIds`-ээ хязгаартай байлга (тоглогч тутамд сүүлийн **200**, үе шат бүрд цэвэрлэнэ). Ингэснээр клиент сүлжээ муудвал сохроор дахин илгээж болно — түүнд нь тэр хэрэг болно.

### 3.8 Мафид тусгайлсан залилангийн эсрэг шалгах хуудас

| Халдлага | Хамгаалалт |
|---|---|
| Пакет чагнаж дүрийг мэдэх | Огт бүү илгээ (§3.4). Бүхэл хамгаалалт нь энэ. |
| Өөрчилсөн клиент хоёр удаа санал өгөх | Сервер тал дээр `hasVoted` олонлог, тоглогчоор түлхүүрлэн, тойрог тутамд. |
| Хасагдсан тоглогч `DAY` чатад үргэлжлүүлэн бичих | Сервер тараахаасаа өмнө `alive`-ыг шалгана. |

| Цагийг өөрчилж эцсийн хугацааны дараа үйлдэл хийх | Сервер `Date.now()`-ыг `phaseEndsAt`-тай **+1.5 сек** хүлцэлтэйгээр харьцуулна; клиентийн цагийн тэмдэглэгээг огт тооцохгүй. |

## 5. Нүүлгэлтэд тэсвэртэй кодын байрлал

```
/packages/rules        <- PURE, no I/O: reduce(state, event) -> state
                          legalCommands(state, playerId) -> Command[]
                          projectFor(state, playerId) -> PublicView
                          resolveNight(state) -> GameEvent[]
/packages/proto        <- command & event schemas (zod / protobuf), version field
/apps/server-colyseus  <- thin: sockets, timers, persistence -> calls /rules
/apps/server-do        <- thin: DO + alarms + hibernation  -> calls /rules  (future)
/apps/mobile           <- Mode A runs /rules LOCALLY; Mode B runs it remotely
```

`/packages/rules` цэвэр бөгөөд платформгүй учраас **Горим A (офлайн хөтлөгч) ба Горим B (онлайн) нэг дүрмийн номыг хуваалцана**. Энэ бол энэ баримт бичгийн хамгийн их хөшүүрэгтэй ганц шийдвэр: нэг монгол дүрмийн текст, нэг багц тест, хоёр тээвэр.
