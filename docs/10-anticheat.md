# Бүлэг 10 — Хууран мэхлэлт, тохиролцоо ба шударга байдал

> **Гол дүгнэлт**
> - Бодит хууран мэхлэлтийн **95% нь техникийн биш, нийгмийн** шинжтэй. Хамгийн их үр өгөөжтэй шийдвэр бол анти-чит систем биш, **мэдээллийн зохиомж**: үхэхэд дүр задрахгүй бол сүнс шивнэх нь утгагүй болно; бүх тоглогч ижил шөнийн санамж авбал хугацаа мэдээлэл алдахгүй; хөтлөгчийн төхөөрөмж дээр «бүх дүрийг харах» дэлгэц огт байхгүй бол хөтлөгч тохируулах боломжгүй.
> - Техникийн хамгаалалт (сервер эрхтэй далд төлөв, Play Integrity, төхөөрөмжийн кластер) бол **хоёрдугаар давхарга** бөгөөд зөвхөн онлайн зэрэглэлийн горимд хамаарна. Офлайн ангийн горимд эдгээрийг бүү барь.
> - Гуравдугаар давхарга бол **commit–reveal аргаар нотлогдох шударга байдал**. Чиний бүтээгдэхүүнд хөтлөгч нь ангийн хүү/охин — дэлхийн хамгийн бага итгэл хүлээдэг оператор. Тиймээс P1/P2 протокол нь энэ бүх досьеийн дотроос **нэг өдрийн хөгжүүлэлтэд ногдох итгэлийн хэмжээгээр хамгийн өндөр** зүйл.
> - **Нэг IP хаяг = хууран мэхлэлт гэж БҮҮ үз.** Ангиараа нэг Wi-Fi дээр байх нь чиний үндсэн хэрэглээ. IP/төхөөрөмжийн кластерын эвристик нь сүлжээний биш, **тоглолтын горимын** шинж чанар байх ёстой.
> - Монголд SMS баталгаажуулалт **$0.16/SMS** (АНУ-д $0.01). 1,000 хэрэглэгч ≈ **$160+**. Бүртгэлд SMS хэзээ ч бүү шаард — зөвхөн зэрэглэлд орох «нэмэлт шат» болгон ашиглаж, сар бүрийн дээд хязгаарыг кодонд шууд хатууд.

## 0. Нэг догол мөрийн тезис

Монголын ангид зориулсан, офлайнаар эхэлдэг Мафи апп-ын хувьд **бодит хууран мэхлэлтийн 95% нь техникийн биш, нийгмийн** шинжтэй. Хамгийн их хөшүүрэгтэй анти-чит шийдвэр бол анти-чит систем огт биш — тэр бол *мэдээллийн зохиомж (information design)*: хэрэв үхэхэд дүр задрахгүй бол сүнс шивнэх (ghosting) нь ямар ч үнэ цэнэгүй; хэрэв тоглогч бүр яг адилхан шөнийн санамж авдаг бол цаг хугацаа юу ч алдахгүй; хэрэв хөтлөгчийн төхөөрөмж дээр «бүх дүрийг харах» дэлгэц хэзээ ч гардаггүй бол хөтлөгч юуг ч тохируулж чадахгүй. Техникийн хатууруулалт (сервер эрхтэй төлөв, Play Integrity, төхөөрөмжийн кластержилт) бол *хоёрдугаар* давхарга бөгөөд зөвхөн онлайн зэрэглэлийн горимд хамаарах ёстой. Гуравдугаар давхарга — **commit–reveal-д суурилсан нотлогдох шударга байдал** — чиний бүтээгдэхүүнд яг ийм учраас хэрэгтэй: хөтлөгч чинь ангийн найз, харин ангийн найз бол дэлхийн хамгийн бага итгэл хүлээх оператор юм.

## 2. Эсрэг арга хэмжээний инженерчлэл

### 2.1 Сервер эрхтэй далд төлөв + тоглогч тус бүрийн багцын шүүлт (T8-ийг засна)

Дүрэм: **клиент өөрт эрхгүй нэг ч байт хүлээж авах ёсгүй, тэр ч байтугай null болгосон талбарыг ч.** `{id:7, name:"Bat", role:null}` гэж бүү илгээ — тэр түлхүүр нь огт **байхгүй** проекц илгээ.

**Юу гэсэн үг вэ?** «Проекц» гэдэг нь нэг том төлвөөс тоглогч тус бүрийн хувьд харах эрхтэй хэсгийг нь тасалж аваад илгээх явдал. Мафи өөрийн багийнхныг харна, иргэн юу ч харахгүй — гэхдээ иргэний утас руу «нууцлагдсан» өгөгдөл ч явахгүй.

Хэрэв чи **Colyseus** (Node, WebSocket, схемд суурилсан) ашиглавал яг энэ механизм нь `StateView` юм (docs.colyseus.io-той харьцуулан 2026-09-15-нд баталгаажуулав). Доорх кодод схемийн `role` талбар нь зөвхөн `StateView`-ээр дамжиж, `mafiaPeers` нь зөвхөн 1 гэсэн шошготой view-д харагдана:

```ts
// schema
const Player = schema({
  name:       t.string(),            // everyone sees
  alive:      t.boolean(),           // everyone sees
  role:       t.string().view(),     // only via StateView
  mafiaPeers: t.array(t.string()).view(1), // only via tag 1
});

// on join
onJoin(client) { client.view = new StateView(); }

// after the deal
client.view.add(playerSchema);           // this player sees their own role
if (isMafia) client.view.add(p, 1);      // mafia also see the peer list
// later
client.view.remove(p);
client.view.has(p);
client.view.subscribe(this.state.events);
```

Colyseus нь нийтлэг талбаруудыг нэг удаа цувруулж (serialise) дараа нь view тус бүрийн талбарыг клиент бүрт тусад нь цувруулдаг.

> **Баталгаажуулалт (2026-09-15):** Дээрх бүх тэмдэглэгээ бодитоор оршдог: `.view()`, `.view(tag)`, `client.view = new StateView()`, `.add()`, `.remove()`, `.has()`, `.subscribe(collection)`. Баримт бичигт дурдсан, энэ досье нуух ёсгүй хоёр анхааруулга: `StateView` нь **v0.16**-д нэвтэрсэн бөгөөд туршилтын `@filter()`/`@filterChildren()` декораторуудыг орлосон; мөн баримт бичиг *«Avoid relying on StateView for large datasets: it is not optimized for that yet»* гэж анхааруулдаг. 12 суудалтай Мафи өрөө бол яг түүний сайн ажилладаг «жижиг өгөгдөл»-ийн тохиолдол. Эх сурвалж: https://docs.colyseus.io/state/view/

Ижил төстэй загварыг энгийн Socket.IO (`socket.id`-ийн өрөө рүү emit хийх), Firebase (`matches/{id}/private/{uid}` доорх uid тус бүрийн баримт + security rules) болон Photon дээр хийж болно.

**Багцын дүүргэлт (payload padding).** Мафийн дүрийн блоб нь иргэнийхээс урт байдаг (багийнхны ID-г агуулна). TLS дотор ч **урт нь** алдагддаг. Засвар: дүрийн багц бүрийг санамсаргүй дүүргэлттэй **тогтмол 256 байт** болгон цувруул. Зардал: ~0.5 хөгжүүлэлтийн өдөр.

**TLS + pinning.** OWASP MASVS-NETWORK-1 нь зөв TLS ба баталгаажуулалт шаарддаг; MASWE-0028 нь аюулгүй бус identity pinning-ийг хамардаг; MASVS-RESILIENCE нь обфускаци, root/эмулятор/дебаггер илрүүлэлтийг хамардаг. Pinning нь энгийн mitmproxy-ийн эсрэг босгыг өндөрсгөнө, гэхдээ root хийсэн төхөөрөмжийг зогсоохгүй — тэр нь хамаагүй, учир нь проекц зөв хийгдсэн бол утсан дээр хулгайлах юм байхгүй. **Проекцоо засаагүй байж клиентийн эсрэг-эвдрэлийн шийдэлд мөнгө бүү үрэ.**

### 2.2 Жигд хугацаа ба хуурамч санамж (T9-ийг засна)

Энэ нь онлайнаас илүү чиний **офлайн горимд** чухал — учир нь утаснууд ширээн дээр 40 см зайтай хэвтэж байгаа.

| Дүрэм | Тодорхойлолт |
|---|---|
| Бүх хүнд санамж очно | Иргэд «Хэн сэжигтэй вэ?» гэсэн санамж авна (юу ч хийхгүй сэжиглэлийн санал, аналитикт л бүртгэгдэнэ) |
| Харилцан үйлдлийн өртөг ижил | Дүр бүрд: 1 бай дээр товших + 1 баталгаажуулах товшилт. Ямар ч үл хамаарах зүйлгүй. |
| Чичиргээ/дуу ижил | Бүх дүрд ижил чичиргээний хэв маяг, ижил дуу, ижил үргэлжлэх хугацаа |
| Шөнийн урт тогтмол | Шөнө яг **T = 35 сек** (тохиргоо 25–45 сек). Бүх үйлдэл ирсэн ч гэсэн **хэзээ ч эрт бүү дуусга** |
| Харуулах jitter | Санамж төхөөрөмж тус бүрд `T0 + U(0, 1500 мс)` дээр бие даан гарна |
| Эрт үр дүн байхгүй | Эмч «чи хүн аварлаа» гэдгээ өдрийн өгүүлэмж хүртэл мэдэхгүй; мөрдөгчийн үр дүн тогтмол цэг дээр гарна |
| Дүүргэсэн багц | Тогтмол 256 байтын үйлдлийн санамжийн фрейм |

Шөнийн шийдвэрлэлтийн псевдо-код (мөн ялалт шалгах дараалал). Үйлдлүүд ирсэн дарааллаараа биш, **эрэмбээрээ** шийдэгдэж, үхэл нэгэн зэрэг хэрэгжиж, нийтийн өгүүлэмж хэнийг үхснийг зарлах боловч **дүрийг нь зарлахгүй**:

```
NIGHT_END:
  actions = collect(all submitted)          // decoys discarded
  resolve in priority order:
    1. role-block / jail
    2. protect (doctor)     -> protectedSet
    3. kill (mafia)         -> if target in protectedSet: no death
    4. investigate (police) -> queue result for the detective only
  apply deaths simultaneously
  emit public narration (who died, NOT their role)
  checkWin()
```

### 2.3 Үхэл юу ч илчлэхгүй (T5-ийг засна, T1-ийг сулруулна)

Бүх горимд үндсэн байдал: **хасагдсан тоглогчийн дүр тоглоом дуустал нууц хэвээр.** Мөн: хасагдсан тоглогчийн өөрийнх нь дэлгэц зөвхөн түүний аль хэдийн мэдэж байсныг харуулна — оршуулгын газрын чат байхгүй, «мафийн баг энэ байна» самбар байхгүй. Шинэ юм мэдэхгүй хасагдсан тоглогч ямар ч хэрэгтэй зүйл шивнэж чадахгүй.

Энгийн/ангийн уур амьсгалд зориулж «Дүрийг задлах» гэсэн өрөөний тохиргоо сонголтоор байж болно, гэхдээ **зэрэглэлийн горимд албадан унтраа**. Зардал: 1 хөгжүүлэлтийн өдөр. Үнэ цэн: ганцхан энэ дүрэм Discord-ийн хажуугийн сувгийн болон шивнэж буй хасагдсан ангийн найзын үнэ цэнийн ихэнхийг устгана.

### 2.4 Дэлгэцийн зураг ба мөр дээгүүр харах (T6, T7-г засна)

| Платформ | Юу боломжтой вэ | API |
|---|---|---|
| Android | Дэлгэцийн зураг, дэлгэц бичлэг, аюулгүй бус гадаад дэлгэцийг **блоклож чадна** | Зөвхөн илчлэх Activity дээр `window.addFlags(WindowManager.LayoutParams.FLAG_SECURE)`; дараа нь `clearFlags`. Анхаар: композиторын гүйцэтгэлд бага зэргийн зардалтай |
| iOS | **Блоклож ЧАДАХГҮЙ.** Зөвхөн илрүүлнэ | `UIScreen.isCaptured`, `UIScreen.capturedDidChangeNotification`, `UIApplication.userDidTakeScreenshotNotification`. **Барихаасаа өмнө боломжтой эсэхийг шалга:** Apple-ийн баримт бичигт 2026-09-15-ны байдлаар `isCaptured` нь **iOS 11.0–27.0** гэсэн хязгаартай (ах дүү симболууд нь ийм дээд хязгааргүй), харин `capturedDidChangeNotification` (iOS 11.0–) ба `userDidTakeScreenshotNotification` (iOS 7.0–) нь нээлттэй. iOS 26 нь `UIScreen.CapturedDidChangeMessage` гэсэн төрөлжсөн NotificationCenter мессеж нэмсэн — орчин үеийн target дээр үүнийг сонго |

iOS блоклож чаддаггүй учраас **нийгмийн албадлагыг** ашигла: илчлэх үед `userDidTakeScreenshot` асвал өрөөний бүртгэлд нийтэд харагдах, хаагдахгүй мөр нэмж, TTS-ээр чангаар унш — *«Тоглогч 4 дэлгэцийн зураг авлаа.»* Ангид энэ нь ямар ч хоригоос хамаагүй хүчтэй сануулга болно.

Илчлэх дэлгэцийн зан үйл (L1 — утсаа дамжуулах):

1. Дамжуулах дэлгэц: «Ширээн дээр тавь. Дараагийн тоглогч: №5» — дэлгэцэн дээр нууц юу ч байхгүй.
2. Тоглогч №5 **«Би бэлэн»** дээр товшино (утас аль хэдийн гарт нь байгаа).
3. Дүр нь зөвхөн **хуруугаа дарж байх хугацаанд** харагдана (хоёр эрхий хуруугаар дарах), бага тодролтой өнгө, **2.5 сек**-ийн дараа автоматаар нуугдана.
4. «Ойлголоо» баталгаажуулах → дэлгэц дамжуулах төлөв рүү буцна.

### 2.5 Дансны бүрэн бүтэн байдал, төхөөрөмжийн хязгаар ба SMS-ийн зардлын урхи (T4, T14, T16-г засна)

**Үнэгүй/хямд дохионууд (2026-09-15-нд баталгаажуулав):**

Эх сурвалж: https://cloud.google.com/security/products/recaptcha

**Утасны дугаарын баталгаажуулалт — амлахаасаа өмнө арифметикийг нь хий.** Google Cloud Identity Platform / Firebase Phone Auth нь **илгээсэн SMS тутамд** төлбөр авдаг (амжилттай баталгаажсан тутамд биш), өдөрт эхний 10 SMS үнэгүй. 2026-09-15-нд Identity Platform-ийн үнийн хүснэгтээс татав: **Монгол (MN) = SMS тутамд $0.16**, харин АНУ = $0.01. Өөрөөр хэлбэл **баталгаажсан 1,000 монгол данс ≈ $160+**, дахин илгээлтийг тооцохоос өмнө. Дээр нь MAU-ийн үнэ: 0–50 мянга үнэгүй маягтай, 50–100 мянга $0.0055/MAU, 100 мянга–1 сая $0.0046, 1–10 сая $0.0032, 10 сая+ $0.0025.

> **Зөвлөмж:** бүртгүүлэхэд SMS-ийг хэзээ ч бүү шаард. Зөвхөн **нэмэлт шатны хаалт** болгон ашигла: зэрэглэлийн горимд орох үед, эсвэл төхөөрөмжийн кластерын тэмдэглэгээний дараа данс сэргээх үед. Төсвөө тодорхой бич, жишээ нь сард 500 SMS = сарын дээд хязгаар $80, тэгээд түүнийгээ **кодондоо хатуу хязгаарла**.

**Android-ийн танигчийн дүрэм — заавал дагах ёстой** (Google Play Families бодлого, 2026-09-15-нд https://support.google.com/googleplay/android-developer/answer/9893335 дээрээс иш татав). Хориотой танигчийн жагсаалт нь ихэвчлэн иш татдагаас урт: **AAID, SIM Serial, Build Serial, BSSID, MAC, SSID, IMEI ба/эсвэл IMSI**. *Зөвхөн* хүүхдэд чиглэсэн апп эдгээрийг дамжуулж болохгүй; **холимог үзэгчтэй апп нь хүүхдээс болон насыг нь мэдэхгүй хэрэглэгчээс эдгээрийг дамжуулж болохгүй** (чиний тохиолдол). Үүнээс тусдаа, ямар ч болзолгүйгээр: *«Device phone number must not be requested from TelephonyManager of the Android API»* (утасны дугаарыг TelephonyManager-ээс шаардаж болохгүй). §2.7-д хамаатай бас нэг заалт: *«Apps must use the Companion Device Manager (CDM) when requesting Bluetooth»* — CDM-тэй нийцэхгүй OS хувилбар руу чиглээгүй бол Bluetooth хүсэхдээ CDM ашиглах ёстой.

Чиний үзэгч 12 наснаас эхэлдэг тул «төхөөрөмжийн хурууны хээ» чинь **App Set ID + Firebase Installation ID + өөрийн хадгалсан GUID + Play Integrity-ийн verdict**-ээс бүрдэх ёстой — AAID эсвэл техник хангамжийн ID (IMEI/serial нь Android 10-аас, MAC нь Android 6-аас хязгаарлагдсан) хэзээ ч биш. Apple-ийн удирдамж ч ижил зүг рүү түлхдэг: 5.1.1(v) нь данс шаардахыг зөвхөн үндсэн үйлдэл нь мөн үед зөвшөөрдөг бөгөөд апп дотроосоо данс устгах боломж өгөх ёстой; Kids Category (1.3) нь төхөөрөмжийн танигч дамжуулдаг гуравдагч талын аналитикийг хориглодог.

> **Баталгаажуулалт (2026-09-15):** `AD_ID` заалт нь урьд нь бичигдсэнээс **зөөлөн бөгөөд нарийн хүрээтэй** — бодлого нь *зөвхөн хүүхдэд чиглэсэн* апп нь API 33+ руу чиглэхдээ `AD_ID` зөвшөөрөл хүсэх **«should not»** (хүсэхгүй байх нь зүйтэй) гэж бичсэн, «must not» биш. Холимог үзэгчтэй 12–18 насны апп-ын хувьд энэ нь зарлагдсан хориг биш, шилдэг туршлага юм. Эх сурвалж: https://support.google.com/googleplay/android-developer/answer/9893335

**Дансны тодорхой хязгаарууд:**

| Дүрэм | Утга |
|---|---|
| Нэг төхөөрөмжийн кластерт үүсгэж болох данс | Эргэлдэх 30 хоногт **2** |
| Зэрэглэлд орохоос өмнөх дансны нас | **≥24 цаг** **ба** **≥3** дууссан энгийн тоглолт |
| 12 тоглогчтой зэрэглэлийн өрөөнд группын дээд хэмжээ | **2** |
| Нэг зэрэглэлийн өрөөнд ижил төхөөрөмжийн кластер | **Хатуу хориг** (энэ нь аюулгүй — §2.7-г үз) |
| Бүртгэлд App Check амжилтгүй болбол | Зөвхөн L1/L2 офлайнд оруулна; зэрэглэлийг хаана |

### 2.6 Итгэлийн оноо, гарсны шийтгэл ба дахин холбогдох хөнгөлөлт (T10, T11, T13-ыг засна)

**Итгэлийн оноо** `TS ∈ [0,100]`, 60-аас эхэлж, шөнө бүр дахин тооцогдоно:

```
TS = clamp(0,100,
      60
    + 6*log2(1 + completed_games)
    - 10*abandon_rate_30d*100/100      // abandons per game
    -  5*afk_kicks_30d
    -  8*upheld_reports_30d
    +  4*(days_since_signup>30)
    +  6*(phone_verified)
    -  25*(device_cluster_flag)
    -  15*(cooccurrence_lift_flag) )
```

Хувинууд: **0–25** → зөвхөн бие биетэйгээ тааруулна (**сүүдрийн дараалал**, тоглогчид хэзээ ч хэлэхгүй); **26–55** → зөвхөн энгийн горим; **56+** → зэрэглэлд тэнцэнэ. Жишиг: Valve-ийн CS Trust Factor ийм зарчмаар ажилладаг — **[баталгаажаагүй]** нарийн тоонууд; Valve-ийн 2017 оны блог бичлэгийг татаж чадсангүй, тоо иш татахаасаа өмнө blog.counter-strike.net дээр шалга.

**Холболт тасрах / орхих бодлого:**

| Элемент | Тодорхойлолт |
|---|---|
| Дахин холбогдох хөнгөлөлт | **90 сек**, суудал хадгалагдана, дэлгэцэнд «Дахин холбогдож байна…» гарна |
| Хөнгөлөлтийн хугацаанд | Суудал автоматаар алгасна (үйлдэл илгээхгүй); тоглоом **зогсохгүй** |
| 90 сек-ийн дараа | Суудал автомат тоглоом руу шилжинэ: жигд санамсаргүй **зөвшөөрөгдсөн** үйлдэл, санамсаргүй санал эсвэл алгасах |
| **Үр дүн хүчинтэй хэвээр** | «Автоматаар ялалт» хэзээ ч бүү өг, тоглолтыг бүү хүчингүй болго — эс тэгвээс гарах нь өөрөө зэвсэг болно (T11) |
| Гарсан хүний үр дүн | Ялагдал гэж тооцно, зэрэглэл бүрэн хасагдана, шагнал байхгүй |
| Шатлан чангатгах | 1 дэх = сануулга · 2 дахь = 15 мин дараалал хаах · 3 дахь = 1 цаг · 4 дэх = 24 цаг · 5 дахь = 7 хоног (ToS-ийн 24 цаг/72 цаг/1 долоо хоног/30 хоног/6 сар шатыг шахсан хувилбар) |
| Жинхэнэ тасалдлын хөнгөлөлт | Нэг тоглолтод **≥3** тоглогч **20 сек**-ийн дотор унавал сервер/сүлжээний гэмтэл гэж үзнэ: шийтгэл байхгүй |

**AFK ферм:** XP болон валют зөвхөн *тоологдсон үйлдлээс* хуримтлагдана (шөнийн үйлдэл, санал, чат/түргэн чатын мессеж). Дараалсан хоёр тойрогт ямар ч үйлдэл хийгээгүй бол → AFK хөөх, орхилт гэж тооцно.

**Үрэлгэх / ялалт солилцох илрүүлэгч.** ≥10 хамтарсан зэрэглэлийн тоглолттой (A,B) эрэмбэлэгдсэн хос бүрд:

```
lift(A,B) = P(B in lobby | A in lobby) / P(B in lobby)
flag if lift > 20 AND winrate(A | B present) - winrate(A | B absent) > 0.25
```

Мөн **2 минутаас богино** хугацаанд дахин дахин ялагддаг мафийн багууд, болон зөвхөн нэг тодорхой дансны байгаа өрөөнд л зэрэглэл цуглуулж байгаа тохиолдлыг тэмдэглэ. Зэрэглэлийн хувьд **Glicko-2**-ийг rating deviation (RD)-тэй хамт ашигла: өрсөлдөгчийн RD өндөр үед авах өсөлтийг таглаж, 10 байр эзлэх тоглолт шаардаж, зэрэглэлийг хэзээ ч шилжүүлэх боломжтой бүү болго.

### 2.7 Нэг IP-ийн зохиомжийн зөрчил — эвристикээр биш, ГОРИМООР шийд

Энэ бол урхи. **Чиний тэргүүлэх горимд бүгд тодорхойлолтоороо нэг сүлжээнд байдаг**: сургуулийн Wi-Fi эсвэл нэг хүний hotspot дээрх 12 ангийн хүүхэд нэг л нийтийн IP, ихэнхдээ нэг дэд сүлжээгээр харагдана. «Нэг өрөөнд ижил IP = хориг» гэсэн гэнэн дүрэм чиний үндсэн хэрэглээг эхний өдөртөө хориглох болно. Дээрээс нь Монголын мобайл операторууд CGNAT ашигладаг байх магадлал өндөр, тиймээс хоорондоо огт хамаагүй мянга мянган хэрэглэгч нэг нийтийн IPv4-г хуваалцаж болно — **[баталгаажаагүй]**; ямар нэг босго тогтоохоосоо **өмнө** өөрийн телеметрт нийтийн IP тутамд ногдох ялгаатай дансны тархалтыг **2 долоо хоног** бүртгэж, эмпирикээр шалга.

Шийдэл: **IP/төхөөрөмжийн кластерын эвристик нь сүлжээний биш, тоглолтын горимын шинж чанар.**

| Горим | IP кластержилт | Төхөөрөмжийн кластержилт | Зэрэглэл | Итгэлийн оноонд нөлөөлөх нь |
|---|---|---|---|---|
| L1 утсаа дамжуулах | цуглуулахгүй | хамаарахгүй | байхгүй | байхгүй |
| L2 нэг өрөөнд олон төхөөрөмж | **илэрхий хүлээгдэж буй зүйл**, дохио биш | дохио биш | байхгүй | байхгүй |
| OP онлайн хувийн | сул дохио, зөвхөн бүртгэнэ | зөвхөн бүртгэнэ | байхгүй | байхгүй |
| OR онлайн зэрэглэл | сул дохио, зөвхөн хамт тохиолдох lift-тэй *хослуулж* ашиглана | нэг өрөөнд ижил төхөөрөмж = **хатуу хориг** | тийм | тийм |

Мөн нэг өрөөнд байхыг **зарласан, урамшуулсан төлөв** болго — агнах зүйл биш:

- Өрөө үүсгэхэд «Бид нэг өрөөнд байна уу?» гэж асууна → `colocated = true`.
- `colocated` бол апп өрөөний дүрэм рүү шилжинэ (нэг чанга яригчаар өгүүлэмж, апп доторх чат байхгүй, FLAG_SECURE-тэй илчлэлт, зэрэглэлгүй) бөгөөд үүнийгээ *дэлгэцэн дээр хэлнэ* — хэн ч зэрэглэлийн тоглолт хийж байна гэж эндүүрэхгүй.
- Нэг өрөөнд байгааг идэвхгүйгээр илрүүлэхдээ **зөвхөн** тоглоомын хувьд аль хэдийн байгаа дохиогоо ашигла: Nearby Connections / локал LAN-ийн өрөө. Зөвхөн хамт байгааг үнэрлэхийн тулд **BLE сканнер эсвэл байршлын зөвшөөрөл бүү нэм** — энэ нь 12+ насны үзэгчтэй апп-ын хувьд Play Families ба App Store-ийн нууцлалын асуудал болно, харин үр өгөөжийг нь чи зүгээр л асуугаад авч чадна.
- Хэрэв сервер **зарлаагүй** боловч нэг өрөөнд байгаа зэрэглэлийн өрөөг илрүүлбэл (ижил дэд сүлжээ + төхөөрөмжийн кластер + хамт тохиолдол), **тоглолтыг энгийн горим руу буулгаад бүгдэд нь хэл**, бүү хориглоор. Хамт байсан гэж хориглох нь гэм зэмгүй ах дүү, ангийн найзуудыг байнга цохих болно.

### 2.8 Дараа нь илрүүлэх: давтан үзэлт, гомдол, сүүдрийн хориг

**Тоглолтын бичлэг (transcript).** Тоглолт тутамд зөвхөн нэмэгддэг JSON-lines хэлбэрийн үйл явдлын лог: `{t, seq, actor, type, payload}`. Тооцоолсон хэмжээ **тоглолт тутамд 5–20 KB** [тооцоолол — өөрийнхөө бодит хэмжээг хэмж]. 100 мянган тоглолт ≈ **2 GB**. Firebase Realtime DB нь хадгалалт **$5/GB**, татаж авалт **$1/GB** (1 GB хадгалалтаас дээш); Firestore-ийн үнэгүй түвшин нь **1 GiB** хадгалалт, өдөрт **50,000** унших, **20,000** бичих (мөн 20,000 устгах).

> **Баталгаажуулалт (2026-09-15):** Хоёр зүйлийг зассан. (a) **Cloud Functions нь үнэгүй Spark төлөвлөгөөнд ОГТ байхгүй** — үнийн хүснэгтийн Spark багана Functions-ийн мөр бүр дээр «Not applicable» гэж бичсэн; сард 2 сая дуудалт, дараа нь сая тутамд $0.40 гэдэг нь *Blaze төлөвлөгөөнд багтсан үнэгүй хэрэглээ* юм. Тиймээс Functions дээр бичлэгийн урсгал барина гэвэл **эхний өдрөөсөө төлбөрийн данс шаардана**. (b) RTDB-ийн татаж авах эрх төлөвлөгөөнөөс хамаарч өөр: **Spark = сард 10 GB**; **өдөрт 360 MB** гэдэг нь Blaze төлөвлөгөөний өдрөөр тооцсон үнэгүй дүйцэл (~сард 10 GB). Spark дээр RTDB-ийн зэрэг холболт = **100** (Blaze = мэдээллийн сан тутамд 200K). Мөн Firebase одоо **Phone Number Verification**-ийг өөрийн гэсэн үнэтэй тусдаа бүтээгдэхүүн болгон жагсаадаг болсон — хуучин Phone Auth-ийн SMS үнээс тусдаа. Эх сурвалж: https://firebase.google.com/pricing

Бичлэг хадгалах нь хямд; харин түүнийг *бүгдэд үзүүлэх* нь хямд биш — давтан үзэлтийг зөвхөн гомдол ба админаар дамжуулан нээ.

Хадгалах хугацаа: **60 хоног**, дараа нь устгана. Тоглогчийн ID-г хадгал, харин харагдах нэр эсвэл модерац хийх шаардлагатай чөлөөт текстийг хэзээ ч бүү хадгал.

**Бичлэг дээр ажиллуулж болох зан үйлийн илрүүлэгчид** (хямд SQL/BigQuery ажлууд):

| Илрүүлэгч | Томьёо | Босгын тойм |
|---|---|---|
| Боломжгүй мэдээлэл | `d1_mafia_hit_rate` = тоглогчийн 1 дэх өдрийн санал жинхэнэ мафид оносон тоглолтын эзлэх хувь | 12 тоглогч/3 мафитай суурь нь 3/11 ≈ **27%**. n=50 тоглолтод: μ=13.5, σ=√(50·0.27·0.73)≈3.14. **≥25** оноход тэмдэглэ (z≈3.7, p≈1.3e-4); **≥27** оноход шалга (z≈4.5) |
| Сүнс тэжээсэн хот | Тодорхой нэг тоглогч эхэлж үхсэн нөхцөлд хотынхны ялалтын хувь | 30 тоглолтод lift > **1.5** |
| Мафийн тохиролцоо | A мафи байхад мафи B дансыг хэзээ ч алдаггүй | ≥**8** хамт тохиолдол, **0** алалт |
| Ботын саатал | Үйлдлийн саатлын хэлбэлзэл | 40 үйлдэл дээр σ < **150 мс** → тэмдэглэ |
| Бүртгэлийн бөөгнөрөл | Төхөөрөмжийн кластер тутамд цагт үүссэн данс | >**3** → App Check нэмэлт шат |

**Гомдол.** Зөвхөн **шалтгааны жагсаалт (enum)** ашигла, чөлөөт текст байхгүй — «Багийнхаа эсрэг тоглосон / Гадуур мэдээлэл дамжуулсан / AFK / Доромжилсон / Ботоор сэжиглэж байна». Ингэснээр монгол хэл дээрх чөлөөт текстийг том хэмжээнд модерац хийх шаардлага үүсэхгүй — ганцаараа хөгжүүлж буй хүн үүнийг хэзээ ч даахгүй. **7 хоногийн дотор ≥3 ялгаатай төхөөрөмжийн кластераас ≥3 ялгаатай гомдол ирвэл** автоматаар дараалалд ор. Шалгагч бичлэгийн давтан үзэлтийг нээнэ. Өөрийгөө **өдөрт ~15 минутын** шалгалтаар хязгаарла.

**Сүүдрийн хориг.** Баталгаажсан хууран мэхлэгчид сүүдрийн дараалалд орно (зөвхөн бие биетэйгээ тааруулна). Үүнийг хэзээ ч бүү зарла — зарласан хориг зугтах аргыг заадаг. `DeviceCheck`-ийн бит (iOS) ба `deviceRecall` (Android, beta)-тай хослуул, ингэснээр дахин суулгахад хориг арилахгүй.
